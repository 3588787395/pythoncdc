## 重要发现：反编译产物不可复现（frozenset 元素顺序）

冒烟测试重新生成 `arg_checkerOK.py` 时出现 1 行差异：
`value[-1] in ('d','m','q','y')` → `('d','y','q','m')`。

实测同一份代码、同一 pyc，仅改 `PYTHONHASHSEED`：
```
PYTHONHASHSEED=0 -> 'd', 'y', 'q', 'm'   （两次运行一致，稳定）
PYTHONHASHSEED=1 -> 'y', 'd', 'q', 'm'
PYTHONHASHSEED=2 -> 'y', 'q', 'm', 'd'
```

**根因**：`core/cfg/code_generator.py` 两处直接按集合哈希序遍历发射常量——
- line 3597-3598：`elif isinstance(value, frozenset): return repr(set(value))`
- line 3902-3903：同上

`repr(set(...))` 的元素顺序由 str 哈希决定，而 Python 默认启用哈希随机化，
故产物顺序每次运行都可能不同。

**影响**：
- 重新生成 `*OK.py` 会产生**无意义的 diff 噪声**（本次 47 个文件中至少 arg_checker 受影响）
- 这是 `strategy_universe.pyc` 等文件 ok/partial **状态抖动**的已知根因之一

**缓解 / 修复方向**：
- 临时缓解：所有批量与回归命令统一加 `PYTHONHASHSEED=0`，保证可复现
- 根治（待下轮）：frozenset 常量按确定性顺序发射。因 `in {...}` 常量重编译后
  仍折叠为 frozenset（集合相等性与顺序无关），故排序是**语义安全**的。
  实现需防混合类型不可比较，建议 key 用 `(type(v).__name__, repr(v))`：
  ```python
  try:
      _ordered = sorted(value, key=lambda v: (type(v).__name__, repr(v)))
  except Exception:
      _ordered = list(value)
  return repr(_ordered)   # 注意：需保持原有括号形态（tuple/set）以维持字节一致
  ```
  改动后须跑满量 402 回归确认零回归。

## 非确定性修复（det-r28）—— 已实测验证

### 量化方法
`PYTHONHASHSEED` 必须进程启动前设定，无法同进程切换 → 跨进程扫描工具
`round_06/test_engineer/nondet_scan.py <seed> <n>`：对全部 305 个 ok 文件反编译，
记录产物 md5，跨 seed 比对。seed 取 0/1/2/3/7。约 0.26s/文件，全量 ~80s/seed。

### 修复前实测
- 305 个 ok 文件中 **9 个（3.0%）在 5 个 seed 下各产生 5 种不同产物**，296 个稳定
- 9 个文件逐行 diff：17 行差异，**100% 是集合/元组字面量元素顺序**，零结构性差异

### 根因（关键：在加载期，不在渲染期）
`core/pyc_loader_v2.py:57-61` 加载 frozenset 常量时直接遍历展开成
`PycSequence._values`，**顺序当场丢失**，后续所有渲染只能继承。
实证：先改了 7 处渲染点（code_generator 两处、ast_generator_v2 两处、
ast_builder 两处、及空集合 set() 处理）后，`arg_checker` 在 3 个 seed 下仍产生
3 种结果；**改掉加载器后才归零**。→ 排查此类问题先查加载期，别只看渲染。

### 安全性论证（实测反证，勿凭直觉）
担心：集合字面量若为 `BUILD_SET` 逐元素构建，顺序会影响指令序 → 排序会破坏字节一致。
实测原始字节码：
```
BUILD_SET 0 ; LOAD_CONST frozenset({...}) ; SET_UPDATE 1 ; STORE_NAME t0_symbol_set
```
源码集合**编译期已折叠为 frozenset**，书写顺序在 pyc 内不可恢复；重编译同样折叠，
frozenset 相等性与顺序无关 → 顺序不影响字节一致性。
旁证：这 9 个文件顺序每次都变却始终 ok。

### 修复
`core/ast_nodes.py` 新增 `ordered_const_items(container)`，排序键
`(type(v).__name__, repr(v))`（混合类型集合如 `{'', 'null', None}` 直接 sorted 会抛
TypeError），异常时降级为 `repr`，再失败保序。空集合仍输出 `set()` 而非 `{}`。
应用到 6 处集合遍历点（加载器 1 + ast_builder 2 + ast_generator_v2 2 + code_generator 2，
code_generator 的 set/frozenset 两分支各一处）。共 5 文件 +69/−9 行。
