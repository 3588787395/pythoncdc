## 重要发现：反编译产物不可复现（frozenset 元素顺序）

冒烟测试重新生成 `arg_checkerOK.py` 时出现 1 行差异：
`value[-1] in ('d','m','q','y')` → `('d','y','q','m')`。

实测同一份代码、同一 pyc，仅改 `PYTHONHASHSEED`：
```
PYTHONHASHSEED=0 -> 'd', 'y', 'q', 'm'   （两次运行一致，稳定）
PYTHONHASHSEED=1 -> 'y', 'd', 'q', 'm'
PYTHONHASHSEED=2 -> 'y', 'q', 'm', 'd'
```

**根因**：`core/cfg/code_generator.py` 两处直接按集合哈希序遍历发射常量——
- line 3597-3598：`elif isinstance(value, frozenset): return repr(set(value))`
- line 3902-3903：同上

`repr(set(...))` 的元素顺序由 str 哈希决定，而 Python 默认启用哈希随机化，
故产物顺序每次运行都可能不同。

**影响**：
- 重新生成 `*OK.py` 会产生**无意义的 diff 噪声**（本次 47 个文件中至少 arg_checker 受影响）
- 这是 `strategy_universe.pyc` 等文件 ok/partial **状态抖动**的已知根因之一

**缓解 / 修复方向**：
- 临时缓解：所有批量与回归命令统一加 `PYTHONHASHSEED=0`，保证可复现
- 根治（待下轮）：frozenset 常量按确定性顺序发射。因 `in {...}` 常量重编译后
  仍折叠为 frozenset（集合相等性与顺序无关），故排序是**语义安全**的。
  实现需防混合类型不可比较，建议 key 用 `(type(v).__name__, repr(v))`：
  ```python
  try:
      _ordered = sorted(value, key=lambda v: (type(v).__name__, repr(v)))
  except Exception:
      _ordered = list(value)
  return repr(_ordered)   # 注意：需保持原有括号形态（tuple/set）以维持字节一致
  ```
  改动后须跑满量 402 回归确认零回归。

### 安全性论证（实测反证，勿凭直觉）
担心：集合字面量若为 `BUILD_SET` 逐元素构建，顺序会影响指令序 → 排序会破坏字节一致。

源码集合**编译期已折叠为 frozenset**，书写顺序在 pyc 内不可恢复；重编译同样折叠，
frozenset 相等性与顺序无关 → 顺序不影响字节一致性。
旁证：这 9 个文件顺序每次都变却始终 ok。

## Round 29：容器字面量中的嵌套三元（region-based-pyc-decompile-iteration）

### 目标与现象
`site-packages/IQEngine/account/order.pyc::save`（98.08%，52 函数中 1 个不匹配）。
原始 98 条指令 / 17 个 `MAP_ADD`（17 对），产物只剩 10 对，**前 7 对全丢**。

### 根因（两层，均由实测栈轨迹证实）
1. `ExpressionReconstructor` 里三元的条件节点压栈后没有"汇合点"概念，永不消费；
   后续 `MAP_ADD` 弹到非 Dict → fallback 新建空 Dict（`ast_generator_v2.py:718`）。
2. 更根本：区域分析器把整个 `save()` 判为 `TernaryRegion`，`BUILD_MAP 0 … MAP_ADD …`
   被区域边界（condition_block off=0 / merge_block off=148）切成两半，各归约一次，
   前序键值对在边界处丢失。

### 修复（2 文件 +186/−0）
- `core/cfg/ast_generator_v2.py`：三元区域的 open/track/close。边界取自指令自身的跳转
  目标——假分支入口 = `POP_JUMP_*_IF_NONE.argval`，汇合点 = 真分支末尾 `JUMP_FORWARD.argval`。
  闭合前做 `test is region['test']` 身份校验，分支内出现其它消费则放弃归约（不误改）。
- `core/cfg/region_ast_generator.py`：条件块栈底仍是未闭合容器时，把整个区域交
  `expr_reconstructor.reconstruct()` 整体归约成一个容器构造表达式，三元作为嵌套 IfExp
  子节点（"嵌套即抽象节点"）。

### 判据：只看栈深会误伤（实测教训）
v1 宽判据（`depth != 1`）造成 **6 个文件倒退**（全量 305→301）。两个误伤根因：
- `dis.stack_effect` 在 3.11 对 `PRECALL` 恒 −1（真实 0）、`CALL` 恒 −1（不随参变）、
  `LOAD_GLOBAL` 带 push_null 时为 2 → 累计后栈下溢；
- 更关键：栈深无法区分「未闭合容器构造」与「多个独立表达式顺序求值」。
  `bar.pyc` 条件块跳转前栈上确实是 2 个元素，但那是 `', '.join(...)` 结果 + 条件值。
v2 改为**逐格标记元素来源、检查栈底性质**（`syms[0] == 'CONTAINER'`），栈效应不可得或
下溢一律返回 False → 6 个文件全部恢复。
