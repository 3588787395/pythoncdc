## 重要发现：反编译产物不可复现（frozenset 元素顺序）

冒烟测试重新生成 `arg_checkerOK.py` 时出现 1 行差异：
`value[-1] in ('d','m','q','y')` → `('d','y','q','m')`。

实测同一份代码、同一 pyc，仅改 `PYTHONHASHSEED`：
```
PYTHONHASHSEED=0 -> 'd', 'y', 'q', 'm'   （两次运行一致，稳定）
PYTHONHASHSEED=1 -> 'y', 'd', 'q', 'm'
PYTHONHASHSEED=2 -> 'y', 'q', 'm', 'd'
```

**根因**：`core/cfg/code_generator.py` 两处直接按集合哈希序遍历发射常量——
- line 3597-3598：`elif isinstance(value, frozenset): return repr(set(value))`
- line 3902-3903：同上

`repr(set(...))` 的元素顺序由 str 哈希决定，而 Python 默认启用哈希随机化，
故产物顺序每次运行都可能不同。

**影响**：
- 重新生成 `*OK.py` 会产生**无意义的 diff 噪声**（本次 47 个文件中至少 arg_checker 受影响）
- 这是 `strategy_universe.pyc` 等文件 ok/partial **状态抖动**的已知根因之一

**缓解 / 修复方向**：
- 临时缓解：所有批量与回归命令统一加 `PYTHONHASHSEED=0`，保证可复现
- 根治（待下轮）：frozenset 常量按确定性顺序发射。因 `in {...}` 常量重编译后
  仍折叠为 frozenset（集合相等性与顺序无关），故排序是**语义安全**的。
  实现需防混合类型不可比较，建议 key 用 `(type(v).__name__, repr(v))`：
  ```python
  try:
      _ordered = sorted(value, key=lambda v: (type(v).__name__, repr(v)))
  except Exception:
      _ordered = list(value)
  return repr(_ordered)   # 注意：需保持原有括号形态（tuple/set）以维持字节一致
  ```
  改动后须跑满量 402 回归确认零回归。

## Round 32：try-finally 内循环尾部布局（shape_c）+ frozenset 常量保留 —— 收尾中

目标：ptradeAccount 135/137 的两个不匹配（order/trade_response_order_update，97/116→30 指令截断）。

### 双重根因（probe 逐步实测）
1. **异常后继被误当 break 目标**：循环体块 230/360 的异常边（try-finally handler 入口 550）
   不是 break 目标。旧逻辑误判后走 break_targets 分支（post_else BFS），绕过 NOP 判别器，
   phantom for-else 被吞并。修复：`_find_loop_else` break 扫描排除 `block.exception_successors`。
2. **NOP 判别器需三态**：bool 无法区分「有 try 无 NOP」（确定非 for-else）与「无 try」
   （不适用，保持原启发式）→ 改 True/False/None 三态（`_loop_else_nop_marker`）。
   实证（nop_marker2.py w1-w8）：try/finally 中 for-else 的 else 子句在 finally normal-path
   副本前必然产生 NOP；普通后继语句必不发；无 finally 时两形态字节码相同不可区分。
3. **显式 return 判别器**（shape_c vs shape_b）：try 范围内 JUMP_FORWARD 越过 finally 最大
   偏移的唯一合法形态是 handler 跳过跳转；展开块末指令是 JUMP_FORWARD 即显式 return None
   （Region(620)），需释放为独立 BASIC 区域发射，不得被 all_blocks 吸收后静默丢失。
4. **frozenset 被误转 tuple**（解析层）：`core/pyc_objects.py::PycCode.to_python_code._resolve_ref`
   把所有 PycSequence 无条件转 tuple，`TYPE_FROZENSET` 一并被转 → 反编译 `(5, 6)` 而非
   `{5, 6}`，重编译产生 BUILD_SET 序列。修复：按 `_type` 分派 frozenset/set/tuple。
   验证（probe_compile_set.py）：`status in {5, 6}` 编译为 `LOAD_CONST frozenset; CONTAINS_OP`
   与原始完全一致。
5. **Continue 抑制**（region_ast_generator）：异常表边界切出的纯回边块（JUMP_BACKWARD→header）
   是循环隐式迭代，不得补发显式 Continue（会改变 try 异常表边界，t_nested orig 40 vs 41）。
   新方法：`_block_is_pure_back_edge_to_header` / `_if_false_path_is_loop_iteration` /
   `_handler_backedge_is_natural_loop_iteration`。
