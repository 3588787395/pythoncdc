# CFG 完备性衡量标准与无感性审计 Spec

## Why

完备占比至今换了四套口径**全部错误**（① 循环论证：拿实现自身 `RegionType` 枚举当分母；② 有过就算：节点类/构造引用存在即计入分子；③ 语料证据口径：拿语料命中/门禁读数定义"能处理"；④ 无限分母：把"任意嵌套组合"当作无限大分母）。根因是缺一条正确的理论标准：

> **"能处理"的判据 = 识别+归约+生成路径存在 **∧** 处理对嵌套无感（局部性不变式成立）。**

无感处理下，任意深度/任意组合由**归纳**得证——一层正确 + 子区域作为黑箱被父级消费 ⇒ 任意深度正确，分母退化为语言语法面 **128 形态**，与深度、组合、语料全部无关。需要把这条标准形式化、落成可执行的逐形态审计流程，并完成全部 128 形态的审计台账。

## What Changes

- **BREAKING（对 KB 而言）**：重写 `wiki/concepts/branch-coverage.md`——从"节点词汇占比 99.2%"改造为"完备性衡量标准"本体（不变式定义、判定分级、证据锚点规范、误解清单、理论→实现映射）
- 新增**逐形态审计台账**：128 形态 × {识别锚点, 归约锚点, 生成锚点, 不变式判定}，以只读代码审计为证据来源
- 对 4 类已知破口（BoolOp×if 前导操作数 / If×continue / Loop 共享尾 / 孤儿子）逐一定位到归约函数与守卫状态——**只审计定位，不修改**
- 审计 except\* 路径（**审计结论推翻初判**：全链已实现——识别 `region_analyzer.py:9731/9813/12701-12709` + `exception_handler.py:93-276` → 归约 `:8724/:9342` → 生成 `region_ast_generator.py:26839-26843` → 发射 `code_generator.py:702`。旧判"零能力"的根因 = 用 3.12 操作码 `PRELOAD_RERAISE` 当 3.11 检测标准）
- 汇总完备占比为三级计数（完备 / 破口 / 零能力），替换旧的 99.2% 单一数字
- 建立持续迭代机制：修复批（fix2/fix3…）落位后复审对应形态 → 台账更新 → 占比重算
- **硬约束：全程不改程序文件、不新增脚本**；全部产出为 KB 文档 + 既有工具读数

## Impact

- Affected specs（KB 页）：`branch-coverage`（重写为标准本体）、`cfg-anatomy`（补充不变式定义引用）、`overview`/`index`/`log`（数字与结论同步）
- Affected code：**零程序改动**。只读审计 `core/cfg/region_analyzer.py`、`core/cfg/region_ast_generator.py`、`core/cfg/ast_generator_v2.py`、`core/ast_nodes.py`、`core/cfg/patch_detector.py`
- 未来影响：fix2/fix3 等修复批次的验收标准可直接引用本台账的破口条目编号（B1–B4）

## ADDED Requirements

### Requirement: 完备性定义标准

系统 SHALL 以 **"完备形态数 ÷ 128"** 作为唯一完备占比。分母 = Python 3.11 语言语法面（97 个 ast 节点类型 + 31 个无独立节点语句形态 = 128），**永不取自实现自身、永不取自语料**。分子按三级判定：

| 级别 | 判据 |
|---|---|
| **完备** | 识别+归约+生成三路径存在 **∧** 无感不变式成立（无已知破口证据） |
| **破口** | 三路径存在 **∧** 不变式被破坏且有证据（归约读取非局部信息且守卫未封闭） |
| **零能力** | 任一路径缺失（无识别 / 无归约 / 无生成） |

占比 = 完备数 ÷ 128。破口与零能力**不得**计入分子。禁止用手改数字覆盖台账汇总。

#### Scenario: 正确计数
- **WHEN** 某形态的归约被证明读取非局部信息且守卫未封闭（如共享尾被外部引用时误吸）
- **THEN** 该形态判"破口"，从分子剔除，占比下降，缺口清单登记破口编号与证据锚点

#### Scenario: 破口封闭后复审
- **WHEN** 修复批（如 fix2）封闭了某破口的守卫
- **THEN** 复审该形态不变式，判定升为"完备"，台账更新，占比自动重算

### Requirement: 无感不变式（局部性不变式）

归约规则 R 作用于区域 A 时，SHALL 满足：

1. **局部消费**：R(A) 的行为只依赖 `L(A) = A.blocks ∪ A.out_edges ∪ A.exception_table`（自己的块集合、出边、异常表）；
2. **黑箱组合**：∀ 子区域 B ∈ children(A)，父级仅经 B 的 entry/exit 接口消费 B，**不窥视 B 内部结构**；
3. **守卫封闭**：当归约必须参考非局部信息（如"汇合块是否被区域外引用"、"continue 目标是否跨区域"）时，该读取必须有封闭守卫（显式判定并排除），否则即为破口。

**归纳论证（为什么分母不是无限的）**：若 R 对单层区域正确（归纳基）且黑箱组合成立（归纳步），则任意深度、任意组合下 R 行为不变——嵌套对 R 不可见。因此"任意嵌套"不构成组合爆炸，完备性只需在形态维度测量。

#### Scenario: 无感成立
- **WHEN** 同一 if 结构出现在顶层、32 层深、try×for×with 交叉内部
- **THEN** IfRegion 归约产出结构相同的区域子树，行为差异为零（若实现如此，If 判完备）

#### Scenario: 无感破坏
- **WHEN** 块归属依赖"该块是否被区域外引用"这一非局部信息且无守卫
- **THEN** 不变式破，该形态判"破口"，无论它在多少语料上恰好通过

### Requirement: 误解清单（反模式目录）

标准文档 SHALL 列明全部已发生/可能发生的误解，每条含**错误做法 / 为什么错 / 正确做法**。至少覆盖 13 条（详§附录，此处为强制目录）：

1. **循环论证分母**——拿实现自身 `RegionType` 枚举当"全部可能分支"
2. **有过就算**——节点类/构造引用存在 = 已覆盖
3. **语料证据口径**——"能处理"由语料命中/门禁通过定义
4. **无限分母**——把任意嵌套组合当作无限组合空间
5. **节点词汇当完备**——97 节点 100% 产出 = 完备 100%
6. **浅层测试当无感证明**——单层正确 ≠ 归纳步成立
7. **门禁读数当完备性**——字节等价率是正确性口径，不是对语言的完备口径
8. **顶层构造粗清单**——34 形态顶层列表冒充语法全集
9. **识别率当完备性**——语料形态命中率与语言完备性是两个维度
10. **维度混淆**——用字节等价（正确性）反驳/替代形态×不变式（完备性）
11. **改工具不改方法**——修正测量脚本但保留错误口径
12. **错误检测标准**——用 `PRELOAD_RERAISE`（3.12 操作码）零引用误判 except\* 未实现；3.11 真实标记是 CHECK_EG_MATCH/PREP_RERAISE_STAR/is_except_star
13. **语料上限当能力上限**——语料深度 32 ≠ 程序能力边界；无感下深度由归纳覆盖

#### Scenario: 新误解入库
- **WHEN** 审计或评审中发现第 13 种口径错误
- **THEN** 追加进误解清单（编号续接），并注明发现场景，标准持续迭代

### Requirement: 逐形态审计台账

系统 SHALL 为全部 128 形态建立审计台账（KB 文档），每形态记录：

| 字段 | 说明 |
|---|---|
| 形态名 | 语法形态（ast 节点名或扩展形态名） |
| 识别锚点 | 区域类型分发处 `file:line` |
| 归约锚点 | 区域构造/臂收集/块归属处 `file:line` |
| 生成锚点 | AST 构造处 `file:line` |
| 不变式判定 | 完备 / 破口 / 零能力 |
| 证据 | 破口编号（B1–B4）、零引用证据、或"无已知破口" |

证据来源 = **只读代码审计**（人工读代码 + 既有工具读数），**禁止**为审计新增脚本。数字由台账汇总生成，**禁止手改**。

#### Scenario: 台账驱动更新
- **WHEN** 任何形态判定变化
- **THEN** 占比、缺口清单、overview/index/log 的数字全部由台账重算同步，页面间不允许出现相互矛盾的数字

### Requirement: 持续迭代机制

标准 SHALL 定义迭代闭环：**修复批落位 → 复审该批涉及形态 → 台账更新 → 占比重算 → 验收引用破口编号**。fix2/fix3 等后续批的 BRIEF/FACTS SHALL 可引用台账条目（B1–B4）作为验收对象。每次迭代后误解清单只增不删（保留历史口径错误的记录）。

#### Scenario: fix2 引用
- **WHEN** fix2 封闭 B1（or 前导操作数丢弃）
- **THEN** 台账 B1 涉及形态（BoolOp 链）复审升"完备"，占比更新，fix2 归档引用台账版本
