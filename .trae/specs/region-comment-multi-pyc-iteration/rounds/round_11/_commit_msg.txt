rcm-r11: fix Pattern C2 tuple-unpack no-SWAP (BUG A guard + BUG B cond_block path) in _adjust_start_date

Pattern C2: Python 3.11 peephole optimizer removes SWAP 2 for in-function
tuple unpack (a, b = c, d), leaving LOAD/LOAD/STORE/STORE in reversed store
order. The _noswap_unpack_result detector existed but had two bugs:

BUG A (guard too conservative, _generate_block_statements L30722): the
post-STORE guard used a whitelist (noise_after) that omitted BUILD_TUPLE /
BINARY_OP, so "a, b = ...; return a, b" and "x, y = ...; return x + y"
were misclassified as having trailing statements and downgraded, losing the
tuple unpack. Replaced whitelist with blacklist of statement-level ops
(STORE/POP_JUMP/JUMP/RAISE/IMPORT/FOR_ITER) + no-return-expression check,
allowing return expressions (LOAD/BUILD/OP + RETURN_VALUE) to pass.

BUG B (block never reaches _generate_block_statements, _if_extract_cond
_instructions L9565): the else-branch entry block (tuple unpack + if
condition merged into one cond_block) was processed by _if_generate_normal
via _if_extract_cond_instructions, which handled each STORE independently
via _build_store_statement, losing tuple unpack semantics. Added Pattern C2
detection (N>=2 consecutive simple-name STOREs, no SWAP/UNPACK, stack>=N)
that builds the tuple-unpack assignment in one shot, with _c2_skip_until to
skip consumed stores. Aligned with _noswap_unpack_result algorithm.
