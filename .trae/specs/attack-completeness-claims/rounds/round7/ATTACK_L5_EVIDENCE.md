# ATTACK_L5_EVIDENCE — L5 证据层攻击：自证循环 / 语料偏差 / 指标性质

> 规范：`attack-completeness-claims` Task 7（spec.md §攻击分层设计 L5 行；tasks.md 7.1–7.5）
> 被攻击对象：「402 认证语料 6617/6617 单元全绿 + 探针全绿 ⇒ 完备」这条主张的**证据基础**：
> 证据从哪来、是否独立、语料/探针是否代表真实分布、单元数与绿率到底度量了什么。
> **纪律**（延续 L4）：
> * 「可复现」与「正确」分开报告；**不以判据绿代替语义结论**；
> * 每个读数给出 `rounds/round7/logs/` 下的原始 JSON 与可复算工具；
> * 结论必须落三类之一：**击穿**（附证据）/ **未击穿且不可证伪**（附结构性理由）/ **不可证伪**（转方法层）；
> * **本轮只测不修**：`core/cfg/**`、`scripts/pyc_verify.py`、`tests/**`、`wiki/**`、`rules.md` 及其它规范目录零改动；
>   证据工具侧新增 `l5_evidence_stats.py`，并修正 `l5_corpus_scan.py` 的一个存在性判定缺陷（见 §2.4，已如实记录修正前后读数）。
> 解释器：CPython **3.11.7**（`D:\Python\python.exe`）；判据尺子：`pylingual/equivalence_check.py`，
> sha256 前 16 位 `9c7567bd6776b36b`（`logs/l5_drift_0000_0065.json` 的 `ruler` 字段）。

## §0 逐项判定（AT-51–AT-58）

| AT | 攻击项 | 判定 | 一句话证据 |
|---|---|---|---|
| **AT-51** | 已记录绿的**可复现性**（drift） | **未击穿** | 用当前判据 + 当前产品重算 402 个认证产物：**402/402 success、6617/6617 单元**，与基线 `baseline/readings.md:29` 完全一致；7 个分片的单元总数逐片相加 = 6617（`logs/l5_drift_*.json`） |
| **AT-52** | 原始源**可恢复性**（源级 oracle 是否存在） | **击穿** | 402 个语料中 **397 个原始 `.py` 缺失，5 个存在但全为 0 字节** ⇒ 有效原始源 **0/402**；探针侧 197 个 stamped 中 **55 个无源码**，另有 **133 个 source-only 探针从未进入任何 stamp** |
| **AT-53** | 证据链**自证循环与共同原因** | **击穿** | 链路 = 探针源（作者手写）→ 本机 `py_compile` → 本产品反编译 → 同一判据 `compare_pyc`；drift 精确复现 6617/6617、self-test 31/31，但 L2 变异漏检 **366/1311 = 27.92%**、L4 语料外判据绿仅 **4/46 = 8.70%** ⇒ 100% 是**判据自洽**，不是独立语义验证 |
| **AT-54** | 语料/探针**形态与规模偏差** | **击穿** | 语料 bytecode 面 **10/32 形态为 0**（dataclass / except* / match / nonlocal / PEP604 / async_for / chain_compare / ifexp / 深度 d3 / d5）；**70/402（17.41%）无函数 code object**、**68/402（16.92%）只有 1 个单元**、**61.44% 的文件 ≤3 个形态**；探针 bytecode 面 **84.26% ≤3 个形态**，中位数 **1** |
| **AT-55** | **测量平面/检测器盲区**（0 是否等于“没有”） | **击穿** | 工具自己声明 **9 类形态 bytecode 不可判定**；语料 bytecode 报 `chain_compare=0 / ifexp=0 / deep_nest_d3=0 / d5=0`，而同批产物的源面报 **33 / 59 / 254 / 144 个文件**（`summary_source_product`）⇒ **0 是“看不见”，不是“不存在”** |
| **AT-56** | **指标性质**（单元数/绿率 ≠ 正确性） | **击穿** | 6617 个单元按代码对象计，**68 个文件各只有 1 个单元（占单元 1.03%）**、**top10 文件占 19.25% 单元**；单元粒度从空模块到 265 单元不等；L2/L4 已证“判绿可语义错、判红可语义对”（L2 漏检 27.92%；L4 判红样本中 12/21 语义相同） |
| **AT-57** | **证据分母/重复计数** | **击穿（口径层）** | 405 个 stamp 文件、**3342 条探针运行记录**，去重后仅 **197 个唯一产物**（**16.96 条/产物**；解析到产物的 3275 条引用仍为 **16.62 条/产物**）；单个 stamp 最多列 **29 个产物**，单个产物最多被 **98 个 stamp** 引用；“174 处标记 / 197 个产物 / 3342 条记录”三套分母并存，无 canonical 口径 |
| **AT-58** | **检测器自检的独立性** | **不可证伪** | `l5_selftest.py` 31/31 通过，但 31 个样本的 ground truth 由同一审计者在本轮构造；xdis 交叉校验只证明“我们的异常表解析 = 判据使用的解析”，不证明检测器完备；缺独立标注语料/第二实现 ⇒ 转方法层（U-06） |

**本轮一句话结论**：
**证据层被击穿。** 6617/6617 作为“同一判据对同一批产物的可复现读数”成立（AT-51），但作为“完备性证据”不成立：
原始源不可恢复（AT-52）、链路自证（AT-53）、语料与探针系统性偏向小而浅的形态（AT-54）、测量平面把“不可见”报成 0（AT-55）、
单元指标不承载语义（AT-56）、证据分母被重复计数放大（AT-57）。因此上一规范 v8 的 100% 只能保留为**形态基线读数**，
不能升级为“语义完备”；L5 的攻击结论直接输入 Task 8 的方法设计。

## §2 证据来源审计（7.1）

### 2.1 证据链拓扑

```
探针源 .py  --(作者手写)-->  py_compile  --(CPython 3.11.7)-->  .pyc
                                                        |
                                                        v
                                              pycdc（本产品）产物 *OK.py
                                                        |
                                                        v
                                        scripts/pyc_verify.py single
                                                        |
                                                        v
                                 pylingual/equivalence_check.py::compare_pyc
                                     （逐 code object 比 CFG/指令/异常表）
```

- **作者/编译器/产品/判据四段都在同一仓库、同一解释器、同一运行环境**；判据本体还在仓外
  （`D:\Desktop\ptrade相关\pylingual\pylingual\equivalence_check.py`，仅以 sha256 前 16 位锚定）。
- 判据只比较**重编译后的字节码形状**，从不执行程序（`baseline/judge_criteria.md` §3 B-01）；
  因此“探针全绿”最多说明“产物重编译后与原件在归一化字节码/CFG 上一致”，不能说明返回值、副作用、异常消息等语义一致。
- 源面审计工具 `l5_features.py` 与判据共享**同一套字节码/异常表假设**（其异常表解析在 `l5_selftest.py` 中与
  `xdis.bytecode.parse_exception_table` 交叉校验，而后者正是判据使用的解析器）。这是一次**同源校验**，
  不是独立校验：双方一起错时，交叉校验仍会通过。

### 2.2 drift：记录绿的可复现性（AT-51，未击穿）

`l5_drift_check.py` 不重新生成产物，直接用当前判据重算仓库中已存的 `*OK.py`：

| 分片 | 行数 | 单元 | 状态 |
|---|---:|---:|---|
| `[0,65)` | 65 | 914/914 | 65 success |
| `[65,130)` | 65 | 612/612 | 65 success |
| `[130,195)` | 65 | 963/963 | 65 success |
| `[195,260)` | 65 | 1169/1169 | 65 success |
| `[260,325)` | 65 | 1334/1334 | 65 success |
| `[325,390)` | 65 | 1084/1084 | 65 success |
| `[390,402)` | 12 | 541/541 | 12 success |
| **合计** | **402** | **6617/6617** | **402 success** |

- 与 `baseline/readings.md:29` 的 `6617/6617、files_failure=0` 完全一致；分片单元数逐片相加 = 6617。
- **正面结论**：记录绿不是“一次性偶然”，在当前判据/当前产物下可复算；判据与产物都没有在本轮发生静默漂移。
- **边界**：这只是一次**同一判据的重复测量**。它排除“记录被篡改/产物被换掉”的一部分风险，
  但不能排除“判据本身看不见语义错”的共同原因（AT-53）。

### 2.3 self-test：检测器自检（AT-58，不可证伪）

`l5_selftest.py` 对 31 个合成样本逐一验证 `l5_features.py` 的 bytecode/source 两平面检测：

- **31 个样本、0 个失败**（`logs/l5_selftest.json`）；含 **1 个负对照**（`NEG_control`，24 个可选检测器必须全部不触发）
  和 **3 个 source-only ground truth**（`pep604`、`chain_compare`、`ifexp`）。
- 对异常表解析与 `xdis` 做逐项交叉校验；语料扫描侧共检查 **703 个带异常表的 code object、0 处不一致**
  （`l5_corpus_forms.json.xdis_exception_table_crosscheck`）。
- **结构性问题**：ground truth 由同一审计者在本轮构造，样本选择、期望值、检测器实现共享同一套认知；
  `match_literal_only` 甚至被显式期望“bytecode 不触发”（工具文档也承认该形态 bytecode 不可见）。
  这不是“检测器被独立证明完备”，而是“检测器与作者预期一致”。要证伪“检测器漏检”，需要独立标注语料或第二实现；
  当前两者都没有 ⇒ 以**不可证伪**入账（U-06）。

### 2.4 原始源可恢复性（AT-52，击穿）

`l5_corpus_scan.py` 对 402 个认证 pyc 逐个查找同目录原始 `.py`：

| 项 | 读数 | 证据 |
|---|---:|---|
| 语料 pyc 可读 | 402/402 | `l5_corpus_forms.json.n_records=402, missing=[]` |
| 原始 `.py` 缺失 | **397/402** | `source_original_missing=397` |
| 原始 `.py` 存在但为 0 字节 | **5/402** | `source_original_empty=5`；5 个文件逐一 `Get-Item` 实测 Length=0 |
| **有效原始源** | **0/402** | `source_original_available=0` |
| 产物 `*OK.py` 可读 | 402/402 | `product_output_available=402` |

- 初版扫描用 `os.path.exists()` 判可用，把 5 个 **0 字节占位文件**计成 `source_original_available=5`；
  本轮发现后把判定改为“存在且非空”，并保留 `source_original_empty=5` / `source_original_missing=397` 两个字段。
  **修正前后都记录在此**，不掩盖工具自身的误计。
- 结论：**语料侧不存在源级 oracle**。任何“原始源含有/不含某形态”“原始源语义如此”的陈述，
  在没有原源的情况下都只能退回产物 `*OK.py`；而产物正是被审计对象，不能用它证明自己。
- 这直接击中 v8 证据链的前提：402 语料的“认证”是**产物级字节码认证**，不是**源码级语义认证**。

### 2.5 探针源与产物的配对率（AT-52/AT-57）

`l5_probe_scan.py` 从 405 个 `rec1_probes*.json` stamp 中收集探针：

| 项 | 读数 | 说明 |
|---|---:|---|
| stamp 文件 | 405 | `stamp_files=405` |
| stamp 内探针运行记录 | **3342** | 本轮重新计数（`l5_evidence_stats.json`） |
| 去重后可解析的 stamped 产物 | **197** | `n_stamped_records=197` |
| 其中同时有 `.py` 源 | **142（72.1%）** | `stamped_with_source=142` |
| 其中只有 `.pyc`、无源 | **55（27.9%）** | `stamped_without_source=55` |
| source-only 探针源（无 stamp） | **133** | `n_source_only_records=133`，从未产生记录判定 |
| 源记录中的 0 字节文件 | **1/275** | `test_repros/round5/_r5_b122a_hang_ok.py`（空文件） |
| 每条唯一产物的平均 stamp 记录数 | **16.96** | `3342 / 197`；解析到产物的 3275 条引用为 **16.62 / 197** |
| 不同 stamp 名 / 单 stamp 最多覆盖产物 / 单产物最多被 stamp 引用 | **404 / 29 / 98** | `l5_evidence_stats.json`；405 个文件中 404 个不同名（1 个重名/重复计数） |

- 能同时做“源↔pyc↔产物↔判定”四段核对的探针只有 **142/197 = 72.1%**；
  其余 55 个 stamped 探针没有源，133 个 source-only 探针没有判定记录。
- 因此“探针全绿”的覆盖面比 stamp 文件数看起来小得多：**405 个 stamp 文件 ≠ 405 个独立证据**。

### 2.6 小结：可复现 ≠ 独立验证

| 问题 | 答案 | 依据 |
|---|---|---|
| 记录绿能复算吗？ | 能，402/402、6617/6617 | §2.2 |
| 复算用的是同一判据吗？ | 是 | `l5_drift_check.py` 调 `pyc_verify.evaluate` |
| 有独立 oracle 吗？ | **没有** | 源 0/402；判据仓外且不执行程序；自检同作者 |
| 判据能保语义吗？ | **不能** | L2 变异漏检 27.92%；L4 语料外判据绿 8.70%、执行差分 14/56 |
| “100%”是什么？ | **判据自洽的形态基线** | 不是语义完备 |

## §4 指标性质分析（7.3）

### 4.1 “单元”是什么

`scripts/pyc_verify.py:122-129`：

- `units_total = len(results)`，`results` 是 `compare_pyc` 对**每个 code object** 的判定列表；
- `units_success = sum(r.success)`；
- 文件级 `status = success` 当且仅当 `units_success == units_total`（全或无）；
- 文件级 `failure` 不影响 `batch` 退出码（`baseline/judge_criteria.md` B-10）。

因此：

1. **一个空模块也算 1 个单元**；一个 4000 条语句的函数也算 1 个单元。单元数不反映语义复杂度。
2. 一个文件的 265 个单元与另一个文件的 1 个单元在总分子/分母中权重相同。
3. “6617/6617”是**代码对象级等价比率**，不是“语句级/路径级/输入级”覆盖率。

### 4.2 单元分布（402 个文件）

| 分组 | 文件数 | 占文件 | 单元数 | 占单元 |
|---|---:|---:|---:|---:|
| 1 单元 | 68 | 16.92% | 68 | 1.03% |
| ≤3 单元 | 97 | 24.13% | 136 | 2.06% |
| ≤10 单元 | 245 | 60.95% | 1089 | 16.46% |
| top10 文件 | 10 | 2.49% | 1274 | 19.25% |

- 分子被少数大文件主导（top10 占 19.25%），同时被大量单单元文件“填充”（68 个文件只贡献 1.03%）。
  这使“6617”既不代表“402 个文件同等重要”，也不代表“语句/路径覆盖”。
- `p50=8`、`p90=39`：一半文件不超过 8 个 code object；语料的典型单元是**小函数**。

### 4.3 绿率与正确性的关系（为何不等于）

| 证据 | 读数 | 对“绿=正确”的影响 |
|---|---:|---|
| L2 变异测试 | 漏检 **366/1311 = 27.92%**（`x=1→x=True` 漏检 83/84 = 98.81%） | 判据对值语义/形参槽位/docstring 等结构性盲区 |
| L4 语料外判据绿 | **4/46 = 8.70%**（语料内 100%） | 判据绿率不能外推到语料外 |
| L4 执行级差分 | **24 样例 / 56 探针 / 14 处差异**（9 个样例） | 判据绿/红与返回值、副作用、异常不一致 |
| L4 判红样本的语义 | **12/21（57.1%）判红但探针面语义相同** | 判红也有假阳性；“红”不能直接当缺陷数 |
| L5 drift | 402/402、6617/6617 精确复现 | 只证明同一判据的确定性 |

- 结论：`units_success/units_total` 的**唯一可辩护含义**是“在 `compare_pyc` 的归一化字节码/CFG 口径下，
  这些 code object 没有可见差异”。它**不**等于“程序在任意输入下语义等价”，也不等于“形态在任意宿主/深度下正确”。
- 因此把 `6617/6617` 写成“完备”是**指标层级跃迁**（从“判据自洽”跳到“语义完备”），
  与 L1 的“128 计数吞掉变体维度”、L2 的“控制流绿掩盖语义错”是同一类错误的证据层版本。

### 4.4 “100%”应如何表述

允许的表述：

> 在 402 个认证产物上，用 `pylingual` 判据重编译比对，**6617/6617 个 code object 在归一化字节码/CFG 口径下无可见差异**；
> 该读数可复现（L5 drift），但**不包含执行语义、不覆盖原始源、不覆盖语料外与深层组合**。

禁止的表述：

> “完备性 100%”“语义完备”“所有 Python 3.11 形态都已正确实现”“6617/6617 证明无缺陷”。

## §7 证据制度补强清单（交 Task 8/9/10）

1. **原始源留存**：每个认证 pyc 必须绑定可读、非空的原始 `.py`（sha256 + 编译命令 + 解释器版本）；
   验收：`source_original_available/402 = 402/402`（当前 0/402）。5 个 0 字节占位不得再计入可用。
2. **独立 oracle**：至少引入一条**非同一判据**的验证路径（执行级语义差分、第二反编译器/参考实现、人工金标样本）；
   验收：独立路径与 `compare_pyc` 的判定一致率、分歧清单、分歧人工裁决记录。
3. **探针四段配对**：每个探针必须同时有 `.py` + `.pyc` + `*OK.py` + stamp，且四者 sha 可追；
   验收：`stamped_with_source/197 = 197/197`（当前 142/197）。
4. **平面标记**：检测器对不可判定形态输出 `N/A`，不得输出 0；bytecode/source 两平面分别报覆盖率；
   验收：所有 `0` 必须附“已观测为 0”或“不可判定”标签，`PLANE_LIMITS` 与报表字段一一对应。
5. **证据分母去重**：以 pyc sha256（或绝对路径 + sha）为唯一 artifact id；同时报
   `unique_artifacts`、`stamp_files`、`stamp_entries` 三个数，禁止用 stamp 文件数冒充独立证据数；
   验收：分母可审计、可去重，174/197/3342 的差异有固定解释。
6. **指标分层**：同时报文件级、单元级、语句/复杂度分层、执行语义差分四个读数；单元级必须标注
   “code object 数、无权重”；验收：任何“完备”结论必须四读数同时给出，且不得只引用单元级。
7. **语料分层配额**：对 32 个追踪形态、3 个深度档、规模档（≤50 / 51–500 / >500 语句）设最低样本数；
   语料零覆盖的 `dataclass / except* / match / nonlocal / PEP604 / async_for` 必须有真实样本或明确记为“合成补样”
   （`match`/`async_for` 探针已补样，`nonlocal`/`PEP604` 仅源面零星出现，不能算真实覆盖）。
8. **选择偏差披露**：所有“402 语料全绿”必须同时写 `402/14237 = 2.82%`、语料来源（IQ/fly 业务模块、无 stdlib）、
   以及“非随机抽样”；验收：报告中出现比例与来源，禁止只写 402。
9. **drift 定位**：drift 只作为“记录可复现”证据，不作为“语义正确”证据；报告必须同时给出 L2 变异漏检率与
   L4 语料外绿率；验收：drift 全绿不得单独支撑完备结论。
10. **自检独立性**：`l5_selftest.py` 的 ground truth 须来自独立作者/独立规范（如 CPython 语法文档 + 编译器行为），
    或由第二实现复核；验收：自检样本清单、作者、复核人、失败样本可追。

## §8 结论与交接

### 8.1 本轮判定

- **AT-51 未击穿**：6617/6617 可复现，记录没有静默漂移；这是本轮的主要正面读数（另一个是 selftest 31/31 的自洽）。

- **AT-58 不可证伪**：检测器自检缺独立 oracle，转方法层（U-06）。

### 8.2 对 v8 “100%” 的处置

- 保留：`6617/6617` 作为 **v8 形态基线**的“判据可复现读数”，并在任何引用处标注判据、语料、解释器、ruler sha。
- 降级：不得再作为“语义完备/形态完备”的唯一证据；判定口径改为 Task 8 的四支柱（判定空间 / 语义差分判据 / 证明义务 / 持续证据）。
- 与既有破口的关系：B214–B218 是**新增证据层根因**；B219 是 **B178（174 标记口径不唯一）** 在探针/产物层的扩展；
  U-06 是 **B170（covered 只验探针存在）** 在检测器层的扩展。均不重复计数，但须在 v9 台账中并列登记。

### 8.3 交接 Task 8

Task 8 的 `COMPLETENESS_METHOD.md` 必须吸收本轮的六个硬约束：

1. 完备性结论必须绑定**可恢复的原始源**与**独立 oracle**，否则只能称“形态基线”；
2. 覆盖读数必须**按平面标记**，不可判定形态报 N/A，零覆盖必须区分“真零/伪零”；
3. 证据分母必须**去重到 artifact**，stamp 文件数不得冒充证据数；
4. 指标必须**分层**（文件/单元/复杂度/执行语义），单元级不得单独支撑结论；
5. 语料必须**分层配额 + 披露选择偏差**（402/14237、无 stdlib、业务模块集中）；
6. drift 只能证明“可复现”，不能证明“正确”；L2 变异漏检率与 L4 语料外绿率必须与 drift 同表出现。
