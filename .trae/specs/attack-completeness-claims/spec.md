# 完备性主张攻击审计与真正完备实现方法 Spec

## 为什么（Why）

前一规范 `attain-true-completeness` 已把形式层三态落账为 **完备 128 / 破口 0 / 零能力 0 = 100%**（v8），并以「25 行逐行深层探针 + 组合级 25 号终表 + 13 误解自查 + 402 语料零回退」为凭。然而该主张自身尚未被攻击过，其**判定链存在结构性可疑点**：

- **粒度错配**：分母 128 = 97 ast 节点 + 31 扩展形态，是「节点/形态计数」；而「完备」要求的是 **节点 × 宿主上下文 × 语义变体 × 组合深度** 全部装配正确。`ast.If` 单节点至少承载 if/elif/else 链、表达式条件、async 宿主、match case 内 if、循环内 if、try 体内 if 等十余变体——按 128 计数天然把变体维度折进分母。
- **判据强度不足**：单元绿来自 `scripts/pyc_verify.py` 的控制流比较；值语义（`1` / `True` / `1.0`）、字符串与引号、注解、docstring、闭包捕获、装饰器顺序、异常类型别名等差异**不在判据内**，「绿」并不等于「对」。
- **证据同源**：探针源、判定器与产品共享同一套 AST 构造/区域假设 → 共同原因失败（common-mode）不可排除；语料与探针都偏小函数、无 f-string / 无类型注解 / 无 dataclass / 无 PEP604 / 无 3.11 `except*` 真实样本。
- **完备性不可证伪**：现口径下「完备」= 人工判读探针全绿；没有**判定空间定义**、没有**覆盖检查器**、没有**语义级差分**，因此任何反例都能被解释为「域外/口径差」。

本规范以**攻击**为主线：从理论到实际逐层攻击上一规范所认为的完备性，暴露其**成立条件与失效边界**，并最终给出**真正完备的实现方法**（判定空间 + 语义差分判据 + 覆盖检查 + 差分 fuzz + 证明义务 + 可证伪门槛）。

## 变更内容（What Changes）

- 新增**攻击面分层**（L0–L6），逐层出证据、逐层判定「击穿 / 未击穿但不可证伪 / 不可证伪」：
  - L0 理论层：C1/C2/C3 不变式是否覆盖全部非局部信息通道；归纳论证前提（基/步）是否真的成立；区域划分（CFG → 区域层次）算法的完备性是否被证明；「嵌套无感」与「必须知道外层」类判据（loop_else / continue 目标 / handler break）的一致性。
  - L1 口径层：分母 128 是否等于语言面（ast 节点集与扩展形态清单的正确性、遗漏与维护机制）；**粒度错配**实证；三态分类（完备/破口/零能力）的互斥性与完备性；「单元绿 ⇒ 完备」推断链的断点。
  - L2 判定层：`pyc_verify` 判据强度（控制流/结构/值/作用域/异常/装饰器/闭包）；共同原因失败；跨函数与模块级覆盖缺口。
  - L3 机制层：已落地 174 处标记的通用性抽检（判据是否形态特化）；守卫族叠加与优先级冲突（if×for×try×match×with×async 同函数）；存留稀窝 B142/B143 的性质判定（形态级缺口 or 归约级缺口）。
  - L4 实现层：语料外真实项目差分；语义等价差分（执行级）；规模与深度边界（>164 层、巨型函数/表达式）；异常/async/生成器/闭包路径。
  - L5 证据层：自证循环与语料偏差；指标性质（单元数 ≠ 正确性）；缺金丝雀/性质测试/差分 fuzz。
- 新增**判定空间定义**（Judgment Space）：把「完备」从 128 计数改写为**有限可枚举的判定空间**（文法族 × 宿主上下文 × 深度档 × 变体槽），并配套**覆盖检查器**（输出 0 未覆盖形态的机器可验证结论）。
- 新增**语义级差分判据**：以「沙箱执行 + 同输入比对返回值/副作用/异常/顺序」为主判据，控制流/AST 归一化比较为辅。
- 新增**差分 fuzz**（属性测试 + 随机程序生成 + 崩溃最小化）作为持续回归面。
- 新增**真正完备的实现方法**交付物 `COMPLETENESS_METHOD.md`（判定空间 + 判据升级 + 覆盖检查器 + fuzz + 证明义务 + 可证伪门槛），并据此落地最小可用工具集。
- 新增**诚实性纪律**：攻击批次必须给出「击穿证据」或「结构性不可证伪理由」；只产出「看起来没问题」的批次一律打回；新发现缺口一律登记新破口号（自 **B163** 起）并如实回灌台账。
- 台账：v8 口径保留为历史，v9 起增加「判定空间覆盖」与「语义差分」两列；**旧 100% 降级为「形态基线达成（v8 口径）」**，新口径的完备结论以判定空间 + 差分 + 覆盖三证齐备为准。
- **BREAKING**：`完备占比 = 完备形态数 ÷ 128` 作为**唯一**完备性依据的口径被废止（保留 128 作为形态基数，改由判定空间/语义差分/覆盖检查三证决定）；对外展示口径与 wiki 台账 v9 同步调整。

## 新增需求（ADDED Requirements）

### 需求：攻击必须可证伪（Anti-Confirmation-Bias）

每个攻击批次 SHALL 产出三类结论之一：**击穿**（附可复现证据：产物 diff / 差分失败 / 覆盖缺口 / 反例 CFG）、**未击穿且不可证伪**（附结构性理由：为什么该攻击无法在现有判据下被判定）、**不可证伪**（现有判据体系根本不足以判定该攻击 → 转为方法层需求）。**禁止**仅以「复跑全绿」结案；只产出「看起来没问题」的批次 SHALL 打回并要求补结构性论证。

#### 场景：批次只报全绿
- **WHEN** 某攻击批次的结案仅为「既有探针复跑全绿、无新发现」
- **THEN** 该批次不予通过，须补「该攻击在何种条件下本可击穿而未击穿」的结构性论证，否则以「不可证伪」入账并驱动方法层补强

### 需求：判定空间显式化（Judgment Space）

「完备」SHALL 由**有限可枚举的判定空间**定义：维度至少含 **形态（文法族）× 宿主上下文 × 深度档（≥3 级）× 变体槽（该形态的已知语义变体）**。系统 SHALL 产出判定空间清单与**覆盖检查器**（输入：判定空间 + 已覆盖证据；输出：未覆盖形态清单，**必须为空**方可宣称完备）。

#### 场景：变体维度被折叠
- **WHEN** 某形态存在 ≥2 个语义变体（如 `ast.If` 在表达式位置/语句位置/循环体内/try 体内/match case 内）
- **THEN** 判定空间 SHALL 将其列为独立条目并要求独立证据；折叠计数的读数 SHALL 标注为「折叠口径」且不得作为完备依据

### 需求：语义级差分判据（Semantic Differential）

「单元绿」SHALL 不再作为完备的充分条件；每个形态条目 SHALL 附**语义级差分证据**：将原程序与反编译产物在同一沙箱、同一输入序列下执行，比对返回值、副作用（文件/全局/属性写入）、异常类型与消息、语句执行顺序。结构等价（AST 归一化）与控制流等价 SHALL 降级为辅证并标注。

#### 场景：控制流一致但语义不同
- **WHEN** 产物与原程序控制流一致、但值语义不同（`1` vs `True`、`1.0` vs `1`、字符串转义、注解/docstring 丢失、闭包捕获变量错误、装饰器顺序颠倒）
- **THEN** 判定器 SHALL 判为**不通过**，并登记为新破口（自 B163 起）

### 需求：判定器共同原因失败排除

系统 SHALL 审计「探针源 → 编译 → 反编译 → 判定」链路的**共同原因**（判定器与产品共享的 AST 构造/区域假设），并以**变异测试**证伪：人为注入已知错误（改常量/改分支极性/删语句/换操作数顺序）到产物，判定器 SHALL 100% 捕获（漏检率 = 0 为目标，>0 即记为判据盲区）。

#### 场景：变异未被捕获
- **WHEN** 任一变异未被判定器捕获
- **THEN** 该变异登记为判据盲区（破口），判定口径降级为「形态基线」并列入方法层补强清单

### 需求：机制通用性抽检与叠加攻击

系统 SHALL 对上一规范落地的 **174 处标记**做**通用性抽检**（每族机制 ≥1 抽检点，判据须证明可迁移到同族任意形态），并 SHALL 执行**叠加攻击**（单一函数内同时含 if×for×try×match×with×async 及其组合），以暴露守卫族优先级冲突与叠加缺口。

#### 场景：机制实为形态特化
- **WHEN** 抽检发现某机制判据依赖具体形态/具体位置而无法迁移
- **THEN** 登记为新破口，机制重写为通用判据并复跑全量门禁

### 需求：稀窝性质判定

存留稀窝 **B142 / B143** SHALL 被明确判定为「形态级缺口」或「归约级缺口」之一：前者 SHALll 计入破口并升为必修；后者 SHALL 说明为何不构成形态级完备障碍，并给出可复现证据。

### 需求：语料外与规模攻击

系统 SHALL 在**语料外真实项目**上做差分（至少含：带类型注解、f-string、dataclass、生成器、async、装饰器链、PEP604、3.11 `except*` 的真实代码），并 SHALL 对**规模与深度边界**（≥164 层嵌套、≥500 语句函数、巨型表达式）做稳定性与正确性攻击，产出边界读数（可降级但须显式声明）。

### 需求：真正完备的实现方法（交付 `COMPLETENESS_METHOD.md`）

系统 SHALL 产出并经评审的方法文档，至少包含四支柱：

1. **判定空间**：形式化定义 + 有限可枚举生成方式 + 覆盖检查器（0 未覆盖）；
2. **判据升级**：语义差分（执行级）为主 + 结构/控制流为辅的判定协议与容差声明；
3. **证明义务**：每条归约规则的不变式 + 覆盖引理（可机检的规则覆盖检查）——把「抽样绿」升级为「规则完备」；
4. **持续证据**：差分 fuzz（属性测试 + 随机程序生成 + 崩溃最小化）+ 金丝雀 + 语料回归的分层证据制度。

并 SHALL 给出**可证伪门槛**：任何「完备」结论 SHALL 同时满足「判定空间覆盖 0 缺口 + 语义差分 0 失败 + 变异测试 0 漏检 + 覆盖检查器 0 未覆盖形态」，否则只能表述为「形态基线达成」。

### 需求：诚实台账与双读数

系统 SHALL 同时维护两套读数：**形态基线**（v8 口径 128 形态）与**判定空间口径**（本规范新增），任何页面/文档 SHALL 同时标注两者，**禁止**只写其中一个或用其一冒充另一。

#### 场景：新破口发现
- **WHEN** 任一攻击批次发现新缺口
- **THEN** 自 B163 起连续编号登记，回灌 `wiki` 台账 §6 与 `rules.md` §7.2，并标注所属层与判定空间条目

### 需求：v3 门禁与纪律沿用

本规范 SHALL 沿用上一规范的纪律：I.4 白名单判据、零语料特判、G3=0 新增前缀方法、G4=0 硬编码上限、触及方法六项 docstring、E 门禁全量（402 八分片 6617/6617 + small34 1568/1568 + quotation 153/153 + tests 基线名单 + IV.2 全绿）、每轮 `rr-v4rNN:` 提交 + push、`rounds/roundN/` 独立证据目录。

## 修改需求（MODIFIED Requirements）

### 需求：完备占比口径（II.1 → v9 双读数）

原口径：完备占比 = 完备形态数 ÷ 128。**修改为**：形态基线占比 = 完备形态数 ÷ 128（保留）；新增判定空间口径 = 已判定条目数 ÷ 判定空间条目数（分母由判定空间生成器给出，≥128 且随发现增长）。两口径**分列不互替**（延续三维度禁互替纪律）。

### 需求：验证序六步（增攻击面与差分面）

原六步 SHALL 增补：**攻击面回归**（本轮新暴露形态的回放）、**语义差分**（对判定空间抽样执行级比对）、**变异测试**（判据漏检率读数）、**覆盖检查**（未覆盖形态数 = 0）。

### 需求：规则文档与锚点维护

`rules.md` SHALL 随本规范更新 §2.4（增补新误解条目）、§6.2（增攻击/差分/变异/覆盖门禁项）、§8（三态双读数 + 判定空间口径），并在每次触及 `core/cfg/**` 后重核 §3.1 锚点表。

## 移除需求（REMOVED Requirements）

### 需求：「分母 128 即完备」的等式口径

**Reason**：128 是节点/形态计数，把「宿主上下文 × 语义变体 × 组合深度」维度折叠进分母，使「完备」判定退化为「抽样探针全绿」；这是上一规范 v8 的结构性弱点，且无法通过追加探针消除。
**Migration**：128 保留为**形态基数**并继续公示（形态基线口径）；完备性判定改由「判定空间覆盖 + 语义级差分 + 覆盖检查器 + 变异测试」四证决定；wiki/rules 读数改为双读数并标注 v8 为历史口径；既有 round1–round10 证据与提交链不变。
