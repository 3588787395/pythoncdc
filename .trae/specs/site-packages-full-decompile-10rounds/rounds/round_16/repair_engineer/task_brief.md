# Round 16 修复任务卡 — W16「多目标链式赋值含属性/下标目标的重建缺陷」

日期：2026-08-24 ｜ 目标 pyc：`site-packages/IQEngine/utils/record_store.pyc`
（Python 3.11，索引 fn=4, match=0.75；唯一有效缺陷函数 `RecordStore.add_record`）

## 缺陷摘要

原始源码 `records = self._record[key] = []`（双目标链式赋值）被反编译为两条损坏语句：

```python
records = []
_record[key] = self      # 属性限定符丢失、值错位
```

假设源码编译后与原 pyc `add_record` 已验证字节级全等（compare_func PASS），根因唯一确定。

## 字节码证据（CPython 3.11 codegen）

```
BUILD_LIST          # []
COPY 1              # 复制待存值供第二个目标
STORE_FAST records  # 目标1
LOAD_FAST self      # ┐ 目标2 容器/键
LOAD_ATTR _record   # │ （3 条指令产出 2 个栈值！）
LOAD_FAST key       # ┘
STORE_SUBSCR        # 消费栈上剩余 []
```

关键事实：**下标目标的容器为属性访问时，gap 含 3 条指令但只产出 2 个栈值**
（LOAD_ATTR 弹 1 压 1）。而现有处理器全部按「每条 LOAD_* 指令 = 一个栈值」建模。

## 根因链条（主缺陷 + 回退放大器）

### 主缺陷：[Round8-07] 混合链处理器 gap 校验失败

位置：`core/cfg/region_ast_generator.py:35263-35387`

- 行 35283-35286：首目标要求「前一条是 COPY 1」——本例满足；
- 行 35300-35316：末目标 gap 直接取 `[prev_store+1 : store_idx]`；
- **行 35341-35355：STORE_SUBSCR 分支硬校验 `len(_obj_key_m) != 2` 且两条都须是
  `LOAD_*`** —— 本例 gap 为 3 条指令 → `_valid_m = False` → 整个混合链放弃；
- 即使放宽条数，行 35347/35348 用 `expr_reconstructor._load_instr_to_ast`（定义于
  `core/cfg/ast_generator_v2.py:2216`）做单指令转换，该函数**没有 LOAD_ATTR 分支**
  （只有 LOAD_CONST/LOAD_NAME/GLOBAL/FAST/DEREF），会退化为占位符 `<LOAD_ATTR>`，
  因此修复不能只改条数判断，还需换用带栈语义的重建。

### 回退放大器 A：`_build_subscript_assign` 遗留回退伪造裸名与 None 值

位置：`core/cfg/region_ast_generator.py:38652`（调用点 21721-21726）

混合链放弃后，残余指令 `[LOAD_FAST self, LOAD_ATTR _record, LOAD_FAST key, STORE_SUBSCR]`
进入通用下标赋值构建：

- 行 38830-38855 正规路径：`expr_reconstructor._process_instruction`（有正确 LOAD_ATTR
  栈语义，ast_generator_v2.py:317-331）得栈 `[Attribute(self,_record), key]` 深度 2 <
  要求的 3（value 已被首目标消费）→ 不命中；
- **行 38857-38889 遗留回退命中并产生损坏输出**：
  - 行 38866-38868：对末条 `LOAD_ATTR` 单独 reconstruct 得 None 后，用
    `Name(str(argval))` 把 `_record` 降级为裸全局名；
  - 行 38877-38883：把 `LOAD_FAST self` 当作赋值值 → `_record[key] = self`；
  - 若 value_instrs 为空（W16-B 形态）→ 行 38883 伪造 `Constant(None)` → `d[k] = None`。

三个失败形态（repro_results.txt）均可由此完整解释：

| 形态 | 触发 | 症状 | 复现 |
|---|---|---|---|
| W16-A | `x = e.attr[k] = v` | 拆两条语句、限定符丢失、值错位 | repro_01–06 |
| W16-B | `self.x = d[k] = v` | 末目标值 None | repro_07–08 |
| W16-C | `a = b = self.r[k] = []` | 中间目标蒸发 | repro_09 |

### 回退放大器 B：首段 `records = []` 吞掉 COPY

[BUILD_LIST, COPY 1, STORE_FAST records] 被按普通单目标赋值发射，COPY(1) 被静默丢弃，
未留给链式归约。修复主缺陷后此点自然消失，但需回归确认不会反向引入 W15-E 类悬空引用。

## 修复建议（供修复工程师参考）

1. **首选**：将 [Round8-07] 的逐条计数校验改为**正向栈深模拟**（参照 R15 W15-B/E' 的
   `_extract_vc_pre_store_statements` 做法）：按操作码栈效应（LOAD_*=+1、LOAD_ATTR=-1+1、
   CALL 等）扫描 gap，按「末目标需消费 N 个值（STORE_SUBSCR:2 / STORE_ATTR:1 /
   简单 STORE:0）」从 store 位置反推 gap 中产出这些值的指令前缀；gap 剩余前缀即容器/键
   表达式指令，交给 `expr_reconstructor.reconstruct`（而非 `_load_instr_to_ast` 单指令
   转换）整体重建 Attribute/Subscript 目标。
2. 守卫放大器 A：行 38866-38883 遗留回退中，「reconstruct 失败 → 用 argval 伪造裸名/
   Constant(None)」的分支应改为返回 None（让上层走更安全路径）或至少拒绝非简单名指令
   （LOAD_ATTR/LOAD_METHOD 等）的 argval 降级。
3. 保持零补丁原则：判据基于字节码结构（栈效应），不做实例特判。
