### 根因假设验证

用假设原始源码 `records = self._record[key] = []`（双目标链式赋值）编译后与原 pyc 的
`add_record` 做 `compare_func`：**PASS（字节级全等）**，且模块级 consts 也全等。
即原始源码确认为双目标链式赋值，缺陷是反编译器无法重建该形态。

## 是否为 W07–W15 残留变体的判断

**结论：不是残留变体，是新家族 W16。**

- W15 处理的是链式**比较**中 COPY(2)/SWAP(2)（比较复制栈顶左操作数）；本例是链式**赋值**
  中 COPY(1)（复制待存值供多目标）。用途、arg、伴随指令序列均不同。
- region_ast_generator.py 已有两条多目标处理路径：
  1. 纯名链 `_chain_result`（a = b = c）：repro_12 控制组证明正常；
  2. `[Round8-07]` 混合链（含 STORE_SUBSCR/STORE_ATTR 目标）：对「每条 LOAD_* 产出
     一个栈值」建模——STORE_SUBSCR 要求 gap 恰好 2 条 LOAD。本例末目标容器为属性访问
     `self._record`，gap 为 3 条指令（LOAD_FAST self / LOAD_ATTR _record / LOAD_FAST key）
     却只产出 2 个栈值，长度校验失败 → 处理器放弃 → 后续回退路径把序列拆成两条独立
     损坏赋值语句。
- 控制实验矩阵（详见 minimal_repros/ 与 repro_results.txt）：
  - `x = d['k'] = []`（下标容器为简单名）→ 正常重建 → 排除「STORE_SUBSCR 参与」单因素；
  - `x = o.a = []`（STORE_ATTR 末目标）→ 正常重建；
  - `x = <e>.attr[k] = []`（下标容器含 LOAD_ATTR）→ **损坏**（10/12 复现文件 FAIL）；
  - `self.x = d[k] = v`（首目标 STORE_ATTR + 末目标 STORE_SUBSCR）→ 末目标值变 None；
  - `a = b = self.r[k] = []`（三目标）→ 中间目标 b 直接蒸发。
