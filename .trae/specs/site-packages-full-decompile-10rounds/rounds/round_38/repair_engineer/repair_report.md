## 修复点

### 1. region_analyzer.py `_identify_boolop_regions` 创建前操作数纯度校验（W38）
walk 循环对非首块已有 STORE break，但最终链可能经其它组装路径合并绕过：
BoolOpRegion@54 的 op_chain 含 block@184（`asset_code = ...`、
`asset_obj = BaseAsset()`、三条 STORE_ATTR 组成的多语句块）作 'and' 操作数，
整个 if 体（语句 + raise）被折叠成单条 and/or return 表达式（输出甚至引用
未定义的 `asset_obj`）。修复：创建 BoolOpRegion 前校验除 entry 外所有
op_chain 操作数不含 STORE_*（经 `_cond_start_offset` 豁免的 entry 前置
语句前缀合法）；触发即 return None，交由 IfRegion 按语句级结构归约。
区域归约算法「一次正确」：表达式级区域不得吞并语句级块。

### 2. region_ast_generator.py `_try_build_ternary_as_if_cond` W39 守卫
merge 块首部的值消费 STORE（目标 == value_target，或 STORE_SUBSCR/ATTR）
已把三元结果存入变量，其后 POP_JUMP 条件（`if np.isnan(last_price):`）读取
的是变量而非栈上值。旧模式 3（CALL）把从 STORE 开始的整段当消费表达式，
输出 `if np(<ternary>): pass`——赋值丢失、IfExp 错位进条件、raise 体丢失。
修复：consuming[0] 为该 STORE 时返回 None，走 store-assign 路径发射
`last_price = <ternary>`，if 条件由后随 IfRegion 归约（父引用子入口）。

### 3. region_ast_generator.py T1 函数调用上下文包装位置校验（W39 后半）
`result = func(ternary)` 的合法形态要求 CALL 位于值消费 STORE 之前
（before_store 段内）。CALL 全部在 STORE 之后时（cond 块首部的
LOAD_GLOBAL np 是后随语句条件的函数装载，被误记为 func_call_info），
包装凭空造出 `last_price = np(<ternary>)`。增加 `_call_before_store`
位置判据，不满足则不包装（经 self.detector.is_call/is_precall 判定）。

### 4. region_ast_generator.py `_generate_ternary` 负极性还原（W39 收尾）
`X if not np.isnan(...) else Y` 的 `not` 被 CPython 折叠进跳转极性
（POP_JUMP_FORWARD_IF_TRUE 直跳 else 值路径，无 UNARY_NOT）。生成端原样
发射正极性测试，重编译为 IF_FALSE——语义相同但逐指令极性不一致。
修复：无 BoolOp 条件链、无 chained compare 且条件块末指令属
`_TRUE_POLARITY_COND_JUMP_OPS`（模块级 frozenset）时，test 还原为
`not <expr>`（op 键用小写 'not'，与 _convert_unaryop_full 的映射表一致）。
重编译恢复 IF_TRUE，逐指令一致。
