## 1. EXC sub-pattern catalog

> The five axes overlap (a `with` function can also use a typed tuple except), so counts
> are reported per distinctive opcode feature, not as a strict partition.

### EXC-1 — `with` statement inside `try` (WITH_EXCEPT_START)
- **Distinguishing opcodes:** `WITH_EXCEPT_START` (and/or `SETUP_WITH`), `PUSH_EXC_INFO`,
  `POP_EXCEPT`, `RERAISE`. Usually `CHECK_EXC_MATCH` **absent** when the handler is a
  catch-all `except:`.
- **What goes wrong:** The decompiler misplaces the `with` block relative to the handler
  and/or the trailing statement. In the catch-all (`except:`) form it drops the
  reraise tail (`COPY / POP_EXCEPT / RERAISE`) so exceptions that should propagate are
  silently swallowed; in the typed form it re-nests the post-handler statement *inside*
  the `try`.
- **Example files (26 files / 57 funcs):** `IQCommon/utils.pyc::load_yaml`,
  `fly/common/future_contract_info.pyc::FutureInfoCache.__refresh_future_info`,
  `IQCommon/data/api_data.pyc::get_dominant_contract_common`,
  `IQCommon/util/fileio_utils.pyc::FileIO.read`, `fly/common/aes_encrypt.pyc::code_encrypt_so`.

### EXC-2 — `try` with conditional `return`s + `except (A, B, …)` (reraise) + trailing return
- **Distinguishing opcodes:** `CHECK_EXC_MATCH` + `BUILD_TUPLE` (multi-type tuple),
  `PUSH_EXC_INFO`, ≥1 `RERAISE`; the try block contains several `RETURN_VALUE`s inside
  conditional branches and a further `RETURN_VALUE` placed **after** the handler region
  (the 3.11 compiler hoists the final return out of the try).
- **What goes wrong:** pycdc (a) **drops a member of the except-type tuple** (e.g. emits
  `except KeyError:` for `except (AttributeError, KeyError):`) and (b) **re-nests the
  trailing return inside the try** (into the `else`/last branch). Recompiled bytecode
  diverges at the `JUMP_FORWARD / PUSH_EXC_INFO / BUILD_TUPLE / CHECK_EXC_MATCH` boundary.
  Verified byte-identical to the real `PositionDict.__missing__` diff.
- **Example files (41 funcs w/ tuple):** `IQEngine/.../finance.pyc::PositionDict.__missing__`,
  `IQCommon/data/finance.pyc::financial_statements`,
  `IQCommon/util/trade_info_utils.pyc::get_user_info`,
  `fly/data/quote_handler.pyc::is_delisting_stock_local`.

### EXC-3 — catch-all bare `except:` / nested `try/except` (no CHECK_EXC_MATCH)
- **Distinguishing opcodes:** `PUSH_EXC_INFO`, `POP_EXCEPT`, `RERAISE`; **no**
  `CHECK_EXC_MATCH` (catch-all) — typically an outer `except:` wrapping an inner typed
  `except` or a `with`.
- **What goes wrong:** The nested handler chain (`COPY / POP_EXCEPT / RERAISE`) is
  mis-handled; the decompiled recompiled bytecode drops instructions / loses the implicit
  propagation of non-caught exceptions.
- **Example files (34 funcs):** `IQCommon/strategy/jq_trans_module.pyc` (several
  `replace_args`), `IQCommon/strategy/wizard_quant_api.pyc::params_analysis`,
  `fly/common/op_station.pyc::OpStation.__new__`, `IQCommon/util/trade_info_utils.pyc::query_strategy_id`.

### EXC-4 — `try/except` nested inside a loop, handler uses `continue`/`return`
- **Distinguishing opcodes:** `FOR_ITER` / `JUMP_BACKWARD` in the same code object with a
  `try/except` region; `RERAISE`/`POP_EXCEPT` boundary at the loop head; handler contains
  `continue` or a `return` that exits the loop.
- **What goes wrong:** pycdc loses the `continue`/re-entry at the loop boundary and/or
  misplaces the handler, so the recompiled bytecode does not match.
- **Example files:** a subset of the non-`with` failing functions that iterate (flagged in
  28 files by loop-presence); reproduced directly below (see `exc_loop_try_continue.py`,
  `exc_loop_try_except.py`).

### EXC-5 — `try/except/finally` (SETUP_FINALLY)
- **Distinguishing opcodes:** `SETUP_FINALLY` + `POP_EXCEPT` + `RERAISE` plus the
  `finally` body.
- **What goes wrong:** pycdc misplaces the `finally` body / merges it with the handler.
- **Coverage note:** **0** of the 154 EXC functions actually contain `SETUP_FINALLY`
  (the 56-file EXC set has no `try/finally` failures), but this is a directly reproduced
  exception-handling failure and is in scope for the try/except/finally category. Repro:
  `exc_try_except_finally.py`.

## 4. Summary for the developer

The EXC failures are dominated by three decompiler weaknesses around exception handling:
1. **`with` + exception handling (EXC-1, 57 funcs):** handler / trailing-return placement
   and the reraise tail are mishandled.
2. **Multi-type `except (A, B)` tuples with a hoisted trailing return (EXC-2, 41 funcs):**
   pycdc drops a type from the tuple and re-nests the post-handler return inside the try.
3. **Catch-all `except:` / nested try (EXC-3, 34 funcs):** the `COPY/POP_EXCEPT/RERAISE`
   chain is lost, swallowing propagating exceptions.

The 11 minimal repros give focused, re-runnable regression targets for each sub-pattern.
