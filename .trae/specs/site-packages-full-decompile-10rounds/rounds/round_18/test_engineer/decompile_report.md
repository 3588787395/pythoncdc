## R18 深化分析（同轮补充）：gtn_request send_service 精确根因

完整 elif 链（5 臂）：
1. isinstance(data, list) → rsp_str = data（J→merge@1016）
2. 'last_tradeday' in data → df 构建 + set_index + **return df**（RETURN 终结臂）
3. 'rows' in data → rsp_str = data['rows']（J→merge）
4. 'data' in data → 内嵌 if/else：then=构建 df 并 return；else=rsp_str=data['data']（J→merge @976，即缺失的那条指令）
5. else → return pd.DataFrame()

反编译产物把链在臂 2 处截断（**RETURN 终结臂被当作链尾**），臂 3/4 与最外层 else 的 return 全部降级嵌套进 else 套件，导致：
- 臂 4 内层 else 落空跳转 J→1016 消失（唯一字节码差异）
- 最外层 else 的 return pd.DataFrame() 错位为臂 4 内的顺序语句

**W17-B 判定规则（移交实现）**：elif 链延续性只取决于「本臂假出口是否指向下一臂条件测试块」，与臂体是否以 RETURN 终结无关。链构建器不得在 RETURN 终结臂处截断；截断后多余臂会连同外层 else 返回值一起错误嵌套。
