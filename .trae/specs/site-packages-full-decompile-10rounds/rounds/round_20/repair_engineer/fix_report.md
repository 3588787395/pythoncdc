# Round 20 修复工程师报告 — 循环家族 C1/C2/C3 + W19 属性目标解包

日期：2026-08-25 ｜ 修复人：编排者（直接实现）

## 1. 根因与修复

### C1「return None ↔ break 歧义」——统一判别式
CPython 3.11 中 for 内 break 与 return None 均编译为
`[POP_TOP, LOAD_CONST None, RETURN_VALUE]`，仅当循环出口为隐式 return None 块时
两种重建重编译等价；出口含实际代码时真 break 必为 `[POP_TOP, JUMP_FORWARD]`，
终态 RETURN 块只能是显式 return。据此在三处发射点补齐同一前提：

| 位置 | 修改 |
|---|---|
| `_generate_block_statements` 通用 break 检测 | 新增 `_loop_exit_is_implicit_return_none` 守卫，非歧义形态发 Return（repro_13） |
| `_process_if_blocks` BREAK 角色分支 | 终态 RETURN 块 + 非歧义出口 ⇒ 发 Return（repro_13 链内臂） |
| `_process_if_blocks` 尾部 return-None→Break 旧改写 | 同一出口前提守卫；歧义形态保持既有行为零回归 |

### C2「IS-NOT-NONE 条件退化」
`_loop_extract_self_loop_stmts` 极性计算只认 IF_TRUE/IF_FALSE，把
POP_JUMP_FORWARD_IF_NOT_NONE 当真值测试 → `if it is None:` 退化为 `if it:`。
补 NONE_CHECK 分支：NOT_NONE ⇒ `Compare(Is, None)`（镜像既有判据），IF_NONE 反之。

### 早退识别缺口（同路径伴生）
早退扫描只认「有值 LOAD 前导」，裸 LOAD_CONST None + RETURN 不被识别 → 落入
Break 兜底。两处孪生扫描均补充 None 形态。C3 多余 continue 系臂渲染错误的伴生
症状，上述修复后自然消失。

## 2. W19：属性/下标目标的元组解包（mysql_conn 攻坚）

`self.conn, self.cur = self.getconn()` 编译为
`[CALL][UNPACK_SEQUENCE 2][LOAD self][STORE_ATTR conn][LOAD self][STORE_ATTR cur]`。
通用帧收集器只接受简单名 STORE_*，属性目标被通用路径撕裂——整个赋值丢失并伪造
`self.conn = None`（578→526 字节）。

新增 `_build_attr_target_unpack(block)`（GBS 入口调用）：值段重建 RHS；N 目标按
源序构成 Tuple(Store)；属性目标=对象装载窗口回拉，下标目标=容器+键双栈窗；
尾部准入收紧——仅认领尾部为空或恰为隐式 return None 的块（含实值 RETURN 或裸
元组构建的块依赖后续块 R23-N6 跨块提升，抢占会拆散组合，quotation
api_get_financial 曾因此退化，已收紧消除）。方法 docstring 含 4 节模板。
