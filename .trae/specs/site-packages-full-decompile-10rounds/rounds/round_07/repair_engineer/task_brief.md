## 一、必须修复的两个根因

### 根因 A：docstring 被丢弃 → 常量表整体错位

- 原函数 `co_consts[0]` 是文档字符串 `'\n    检查用户策略在升级过程中是否涉及量化方法和库变动。\n    :param strategy_content: ...'`，反编译输出不含它。
- CPython 3.11 规则：有 docstring 时 `const[0]=docstring`、`None` 懒插入；无 docstring 时 `None` 占据 `const[0]`。丢失 docstring 使所有 `LOAD_CONST`/`KW_NAMES` 的 arg 错位 1。
- 最小复现：`decompile("def f(x):\n    'doc here'\n    return x + 1\n")` 输出丢失 `'doc here'`。

**修复方向**：函数定义生成路径需检测"函数体第一个语句是字符串常量表达式"（AST 上为 `Expr(Constant(str))` 且位于函数体首），并将其作为 docstring 渲染回源码；模块级与类体的首个字符串常量同理。注意不要误伤"首语句是有副作用的字符串赋值"（见 repro_12，`s = 'text'` 不是 docstring）。

### 根因 B：嵌套 if 被扁平化为 and 链

原字节码形态（offset 为 check_strategy 内绝对偏移）：

```text
552 POP_JUMP_FORWARD_IF_NONE      to 600   ← 外层条件 false → else 块入口(600)
554 LOAD_FAST                     strategy_path
556 POP_JUMP_FORWARD_IF_NONE      to 598   ← 内层条件 false → then 块末尾 JUMP_FORWARD(598)
598 JUMP_FORWARD                  to 672
600 LOAD_GLOBAL                   NULL + open   ← else 块入口
```

反编译器把两个条件折叠成 `if A and B:`，只产生一个 false 跳转，目标无法同时等于 600 与 598。

**判定规则（关键）**：只有当各子条件的 false 跳转目标指向**同一块**时才是真正的 and 链，才允许合并输出 `A and B`；否则必须保持嵌套 if 结构（外层 else 归外层条件）。or 链同理按 true 跳转目标一致性判定（见 repro_07）。
