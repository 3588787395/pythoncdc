# Round 19 修复工程师报告 — W17-B：elif 链 else-return 提升前提缺失

日期：2026-08-25 ｜ 修复人：编排者（子代理基础设施故障，按 R16/R17 先例直接实现）

## 1. 根因链（测试报告 → 偏移级证据 → 实证闭环）

测试工程师证实 W17-B（`_check_elif_chain` 在裸 return 块处 bail 导致链截断）后，
编排者进一步实证发现 **bail 本身无害**——父级 `elif inner_else_blocks:` 回退会正确设置
`final_else=[裸return块]`（trace：`RET ret=DICT conditions=[120] final_else=[170]`）。
真正的丢失点在**生成端**：

1. `_if_generate_elif_chain` 正确产出 `[If(rows){orelse:[If(data){orelse:[Return []]}]}]`
   （插桩：`ELIF_CHAIN entry=94 nconds=1 fe=[170] -> orelse_n=1`）；
2. 调用方 `_if_generate_full_elif_chain` 的「else-return 提升」优化
   （region_ast_generator.py 原 L9923-9987）：当链尾 elif 的 orelse 恰为单条 Return 时，
   将其提升为链后尾随语句、清空 orelse；
3. 该提升的字节码等价**前提**是「链后无实际代码」（merge 为隐式 return None，
   arms 经 JUMP_FORWARD 汇入）。既有守卫只验证了 merge_block 有值且非隐式 return 的情形
   （get_valuation_info 案例），**merge_block=None 时检查被跳过、提升照常发生**；
4. IfRegion@94（内层链）merge_block=None，而真实 merge=@174 `return list(rsp)`：
   提升 → `Return []` 从 orelse 拆为兄弟语句 → 重编译丢失 JUMP_FORWARD→174
   （1132→1130 字节）→ 落空路径误吞 return（语义实锤见 semantic_impact.txt）。

## 2. 修复内容（前提收紧，非补丁）

文件：`core/cfg/region_ast_generator.py`

- `_if_generate_full_elif_chain` 内 `_can_lift_else_return` 判据补全：
  `_merge_block is None ⇒ _can_lift_else_return = False`（前提不可证则禁止等价变换）。
  算法依据：字节码一致性约束——变换合法性必须可证明；保留 `else: return X` 原位发射时，
  arms JF 越过 else 体直达函数尾隐式 return，与原字节码逐指令一致。
- 方法 docstring「特殊处理」节同步记录该约束（W17-B 引用）。

无新增方法；无 `_fix_/_patch_/_fallback_` 等反模式前缀；未触碰其他 *OK.py。

## 4. 残留项（移交 R20）

round_19 复现套件剩余 2 例属**循环相邻家族 C**（非 _check_elif_chain 产物），根因已定位：

- **C1（repro_13）**：for 循环体内显式 `return None` 的规范布局
  `[POP_TOP(迭代器清理), LOAD_CONST None, RETURN_VALUE]` 被
  `_generate_block_statements` 的通用 break 检测（~L34773）误判为 break。
  判别式：真 break = `[POP_TOP, JUMP_FORWARD→exit]`；return = 终态 RETURN_VALUE。
  同型缺陷历史成因：该规则本服务于 try 内 break 的编译变体。
- **C2（repro_12）**：while 循环内 `POP_JUMP_FORWARD_IF_NOT_NONE` 条件被重建为
  真值测试（`it is None` → `it`），NONE_CHECK_OPS 在该条件提取路径缺失处理。
- **C3（repro_13 伴生）**：else 臂末尾 JUMP_BACKWARD 被追加显式 `continue`
  （与 r102 PURE_CONTINUE 分支尾处理相关的 for-merge 归属问题）。

另：批量回归发现 11 个索引陈旧 ok 条目（HEAD 即不匹配，非本轮引入），
建议 R20 用官方 batch 工具全量重审计后修正索引。
