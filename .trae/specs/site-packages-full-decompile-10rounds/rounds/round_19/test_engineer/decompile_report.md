## 3. W17-B 根因结论：**证实（CONFIRMED）**

### 3.1 静态定位（core/cfg/region_analyzer.py）

- `_check_elif_chain` 定义：region_analyzer.py:15197
- 早退守卫：**region_analyzer.py:15307-15308**
  ```python
  if len(first_else.conditional_successors) != 2:
      return None
  ```
- 相关早退分支：15272-15280（`_then_has_ctrl_exit` 路径）、15198-15199（无 else 块）
- 深层递归调用点：15786（`deeper_elif = _check_elif_chain(first_else, inner_else_blocks, merge_)`）；顶层调用点 15837

### 3.2 运行时追踪证实（sys.settrace，未改动项目代码）

对 repro_01（同构骨架）反编译全程追踪 `_check_elif_chain`：

```
CALL else_blocks=5 cond_succ=[2, 2, 0, 0, 1]   # 外层链展开：第 3 个块 cond_succ=0（裸 return）
LINE 15307 GUARD first_else.cond_succ=2
  CALL else_blocks=1 cond_succ=[0]             # 深层递归：first_else 即裸 return 块
  LINE 15307 GUARD first_else.cond_succ=0
  LINE 15308 EARLY_RETURN_NONE                 # ★ 在 15308 提前退出
  RET -> None                                  # 深层 elif 展开被拒绝 → 链被截断
RET -> <elif_info>                             # 父级仍返回"残缺链"，裸 return 的臂归属丢失
```

repro_09（扁平 5 臂链）呈现完全相同的 `[2,0,...] → [0]-bail` 序列。全文见 `trace_evidence.txt`。

### 3.3 因果链条（证据闭环）

1. 守卫在 `first_else.cond_succ=0`（裸 return 块）处触发 → 深层展开返回 None（trace 证实）；
2. 父级拿到截断的 elif_info，把裸 return 渲染为后续语句而非 `else:` 臂（decomp_* 文本逐例证实）；
3. 重编译后缺失该臂对应的 `JUMP_FORWARD→merge`（偏移级 diff 证实）;
4. 执行行为改变（semantic_impact.txt）：repro_01 输入 `{'rows':[1,2]}` 原始返回 `[1,2]`、反编译产物返回 `[]`；
   repro_09 n=35 `'m:b'`→`'r2'`；repro_11 n=25 UnboundLocalError→`'e'`；repro_13 `[None,1]` None→`[]`。

### 3.4 边界细化（重要补充）

- 该 bail 在 **PASS 基线 repro_17 中同样触发**（trace 对照）：单层链场景下兜底渲染恰好重建出正确结构。
- 缺陷**显现条件**：截断链必须与外层区域组合（嵌在外层链的 else 臂内 / 多臂扁平链 / 循环体内）。
- 单独的"裸 return 最终 else"不触发缺陷（repro_16 PASS）——需要存在更深层的条件结构可供截断。
- repro_12/13 属相邻家族（循环区域重建：return→break、条件改写），非 _check_elif_chain 直接产物，单列。

## 6. 结论摘要

1. **验证结果**：4/5 函数字节级一致（80%）；唯一不一致为 `send_service`（1132 vs 1130，差 1 条 JUMP_FORWARD）。
2. **根因**：W17-B **证实**。`_check_elif_chain` 在 region_analyzer.py:15307-15308 以 `len(first_else.conditional_successors)!=2` 提前退出，拒绝展开以裸 return 块为 first_else 的深层链，导致该 return 的 `else:` 臂归属丢失、被渲染为落空语句，重编译后对应 JUMP_FORWARD→merge 缺失，并造成可执行的语义错误（非纯字节码噪声）。
3. **复现**：18 例最小实例，修复前 13 例 FAIL（72%）；W17-B 主家族 11/11 触发，相邻循环家族 2/2 触发，5 例基线 PASS 需保持。
4. **修复建议方向**（供开发参考，未实施）：当 first_else 为裸 return 块（cond_succ==0）且其所在链仍有更深层条件结构时，不应直接 return None，而应将该块识别为当前层的 final_else 臂继续展开。
