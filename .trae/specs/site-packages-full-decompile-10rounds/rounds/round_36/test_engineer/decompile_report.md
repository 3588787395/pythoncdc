## 根因（字节码证据）

字节码布局（create_trade @186..234）：

```
block@104..188: STORE_ATTR _trading_dt; STORE_ATTR _price.._tax (5 条赋值);
                LOAD_FAST trade_id; POP_JUMP_FORWARD_IF_NONE → 194
block@190..192: LOAD_FAST trade_id; JUMP_FORWARD → 232      # true 值
block@194..222: LOAD trade; LOAD_METHOD _make_id; CALL 0    # false 值
block@232..344: LOAD trade; STORE_ATTR _trade_id; ...; RETURN_VALUE
```

- 条件块 block@104 是**双角色块**：它同时是 BoolOpRegion@76
  （`trading_dt or env.trading_dt`）的 merge 块，又是三元
  `trade_id if trade_id is not None else trade._make_id()` 的条件块。
- **缺陷家族 W36**：`BoolOpRegion.can_be_ternary_header` 要求
  `self.entry == block`，块 104 是 merge 块而非 entry → 多态判定返回 False →
  `_can_be_ternary_header`（region_analyzer.py:17853）拒绝 → 三元区域从未创建，
  diamond 只留下 BASIC 块，被通用块语句路径误发射为 if/else + 裸 return。
- 探针实证（probe_regions.py）：修复前 5 个区域中无 TernaryRegion/IfRegion，
  190/194/232 均为孤儿 BASIC Region。
