## 修复点（按区域归约算法 4 原则）

### 1. region_analyzer.py `BoolOpRegion.can_be_ternary_header`（识别端）
新增 merge 块双角色分支：`block is self.merge_block` 时放行 ternary 识别
（原版要求 `self.entry == block`）。依据：merge 块的 pre-STORE 部分归 BoolOp
（值消费），post-STORE 是下一条语句——下游区域 entry == 上游 merge 块是 R35
已确立的双角色合法形态（与 R35 value_target 变体同构）。仅放行 entry /
merge_block 两个消费者边界，op_chain 条件块不放行（防止拆碎条件链）；
两种形态均保持「非 LoopRegion.condition_block」守卫。docstring 按
算法依据/判据/生成端配套三节模板重写。

### 2. region_analyzer.py `_detect_ternary_pattern` skip_ternary 守卫（识别端）
skip_ternary 循环仅认可 `existing.entry == block` 升级路径；补
`elif block is existing.merge_block: can_upgrade = True`（双角色下游，
BoolOp 已完整归约，不否决）。

### 3. region_analyzer.py merge 扫描 STORE_ATTR 分支（识别端）
merge 扫描此前只识别 STORE_SUBSCR 与 STORE_FAST/NAME/GLOBAL/DEREF；
`obj.attr = <三元>` 的 merge 块 `[target loads..., STORE_ATTR]` 扫描落空 →
merge_context=None → 三元被误判为「值上下文」，被虚假外层三元吞并
（repro_02 实证输出 `v = b if a else x if x else y`）。新增 STORE_ATTR
分支：仅当 STORE_ATTR 之前的非噪音指令全部是目标装载（LOAD_*/COPY）时置
`merge_context='store'`（value_target 保持 None，与 STORE_SUBSCR 同构）；
存在 CALL/BINARY_OP 等中间消费指令时保持 None（值上下文，交通用重建）。

### 4. region_ast_generator.py `_try_build_ternary_store_assign` after-store 守卫（生成端）
STORE 消费点之后的指令原始重建为语句时，先检查 merge 块是否为下游结构化
区域的 entry（R10f3 结构化判据：entry 指针 + region_type != BASIC + 向块外
延伸 + 未生成，**不排除 block_to_region owner**——下游区域恰是该块 owner
是双角色块常态，`_downstream_region_entry` 的 owner 排除语义在此不适用）。
是则跳过原始重建，留给顶层依「父引用子入口」派发下游区域（否则下游三元的
条件前导被压成裸 `Expr(Compare)`，repro_08 实证）。

### 5. region_ast_generator.py `_generate_ternary` cond 前缀上游值消费守卫（生成端）
R61 STORE_SUBSCR/STORE_ATTR pre-statement 分支补守卫：cond_block 同时是
另一个 TernaryRegion/BoolOpRegion 的 merge_block 时，块内**第一条 STORE**
（上游值消费点）跳过重建（栈视角错位会产出幽灵 `o.x = None` 占位，
trade.pyc 的 `trade._trading_dt = None` 实证）；后续 STORE（真实
pre-statement，如 `_price.._tax` 五条赋值）不受影响仍走 R61 重建。
与既有 MAKE_FUNCTION 分支的 `_cond_block_is_other_ternary_merge` 判据同构。
