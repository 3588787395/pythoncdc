日期：2026-08-23 ｜ 发起：测试工程师 ｜ 目标：修复「分支内循环吞并合并点后兄弟语句」缺陷家族，使 compile_help.pyc 全函数字节级匹配。

## 1. 根因证据（偏移级）

### 1.1 目标 pyc 缺失块

`site-packages/IQEngine/utils/compile_help.pyc` 的 `compile_strategy`（原 974 字节 vs 反编译 932 字节）：
反编译产物丢失偏移 **876–916** 整块：

```
876 LOAD_FAST error
878 LOAD_ATTR stacks_length
888 LOAD_CONST 0            ← co_consts[6] 缺失同一字面量
890 COMPARE_OP ==
896 POP_JUMP_FORWARD_IF_FALSE → 918
898 PUSH_NULL / LOAD_FAST error / LOAD_ATTR add_stack_info
912 LOAD_FAST item
914 CALL_FUNCTION_EX 0
916 POP_TOP
```

即源码 `if error.stacks_length == 0: error.add_stack_info(*item)`（item 为循环泄漏变量）被整体丢弃；
首个差异 `[22]`：offset=102 `POP_JUMP_FORWARD_IF_FALSE to 966`(ORIG) vs `to 924`(DEC)，为 −42 字节连带位移。

### 1.2 区域级实测证据

对最小复现转储 `RegionASTGenerator(cfg)` 区域结构：

- **丢弃形态**（except handler 内）：`LoopRegion.blocks=[72,86,88,122] orelse=[122]`，其中 blk@122 是
  尾随 if 头部（`POP_JUMP_FORWARD_IF_FALSE->178`）；对应尾随 IfRegion 建成 `blocks=[122,144,172,178],
  merge_block=None, else_blocks=[178]`，最终从未发射。→ 循环区域把 FOR_ITER 耗尽目标块（后续兄弟语句的
  entry）吞进自身 blocks+else_blocks，违反每块唯一归属。
- **伪 else 形态**（普通函数尾）：`LoopRegion.blocks=[36,50,52,86] orelse=[86]`；尾随 IfRegion 本身正确
  （blocks=[86,118], merge=146, 无 orelse），但发射产物多出 `else:` 吸收 raise（co_code +4 字节、跳转改变）。
- **对照组**：同结构去掉分支内循环 → 无 LoopRegion 过度声称，全部 PASS。触发条件 =
  **if/else 分支内含循环 且 for_iter_exit 目标块是合并点上后续兄弟语句的头部**。

## 2. 修复线索文件与方法

按优先级：

1. `core/cfg/region_analyzer.py`
   - `_find_loop_else`（≈L4219-4348）：for 循环把 `for_iter_exit` 直接作为 else 块入口返回；
     L4336-4348 的 R59 回退在 `for_iter_exit` 为纯 JUMP_FORWARD 块时返回 `[for_iter_exit]`，
     但未检查该块是否含条件跳转指令（即是否是下一 IfRegion/TryRegion 等结构化区域的 entry）。
     建议：当 `for_iter_exit` 是其他结构化区域 entry（或其末条指令为 POP_JUMP/JUMP_IF 类）时，
     不得将其计入 loop.blocks / else_blocks。
   - 循环 body 收集主流程（≈L3238-3618）：确认 body 集合把出口目标块一并纳入的位置。
   - `_is_loop_exit_block`（L2020）/`_compute_in_loop_if_merge`（L2040）：循环出口边判据参考。
2. `core/cfg/region_ast_generator.py`
   - `_loop_generate_for` 的 else_blocks 过滤段（≈L3650-3786）：现有排除仅两类——
     其他 LoopRegion 的 `for_iter_setup`（L3673-3681）、祖先 IfRegion 的 merge_block 且该祖先
     在 `_generating_regions` 中（L3693-3702）。需补充：被声称块是任一结构化区域 entry 时强制排除，
     并保证该 entry 由其归属区域生成（当前 except handler 内表现为静默丢弃，疑似与
     `_generated_blocks` 提前标记或 TryExceptRegion 收缩顺序有关）。
   - 参考既有同族修复注释：L3682-3692（get_valuation_info 案例）；r05_backup L12411 起
     R15-N5「IfRegion.merge_block 同时是嵌套 LoopRegion 的 for_iter_exit」。
3. `core/cfg/code_generator.py`：伪 else 的最终输出层核对（低优先，Q 组证据显示 IfRegion 结构本身正确，
   伪 else 可能在 AST→代码转换阶段引入，定位后如根因在前两层则无需改动）。
