## 一、缺陷根因（证据充分，已字节级验证）

反编译器对 `getPboxAccount` 的 CFG 汇合点重建错误，产生三个共生症状：

1. **W14-B 裸 return 丢弃**：`if <cond>: <副作用语句>; return` 形态中分支尾的裸 `return`
   （字节码 `LOAD_CONST None; RETURN_VALUE`）被当冗余删除。orig 三处：
   offset 550–552、868–870、1228–1230。
2. **W14-A 链扁平化错写**：orig 为「外层 if/else + 内层 if/elif/else 三臂链」
   （完整重构源码见 test_engineer/decompile_report.md §二），被错写为扁平
   `if A and logout or login:` —— elif 臂条件 `A and not logout` 的 `not` 丢失、
   嵌套 `if login / else: return 'logout'` 被折叠进布尔链、最终 else 臂的日志语句
   被挪到链后。跳转极性铁证：orig 950 `POP_JUMP_FORWARD_IF_FALSE→1294` 与
   954 `POP_JUMP_FORWARD_IF_TRUE(logout)→1294` 同指尾日志臂，仅 elif 链可产生；
   decomp 944/948/952 是 `(A∧B)∨C` 布局。两者真值表不同（语义级损坏）。
3. **W14-C 共享尾部 return 错位**：四路汇合的单一 `return pboxAccount`
   （offset 1350；前驱 612/928 JUMP_FORWARD + 1288 JUMP_FORWARD + 1348 fallthrough）
   被移入创建臂内联，函数尾变成隐式 `return None`。

**验证方法**：对 decompiled 输出做最小补丁（补回 3 处裸 return、恢复 elif 链、共享 return 回位），
重编译后 getPboxAccount 与 orig 字节级一致（d:\Temp\opencode\r14_final_verify.py，
产物 r14_pb_fixed.py）。修复目标即让 pycdc 直接产出等价源码。

**排除项**：无 try/finally、无循环、无 with；`LOAD_GLOBAL NULL+x; LOAD_ATTR` 方言随源码形态
自动复现（decomp 本地重编译同为 13 ATTR/8 METHOD 分布），无需处理。

## 二、嫌疑方法线索

1. 汇合点/支配树计算：识别"多后继汇合到单一 return"的结构。重点排查把
   `JUMP_FORWARD→<LOAD_FAST x; RETURN_VALUE>` 的前驱块当作"该分支自有 return"的逻辑——
   正确行为是保留为链结构并把 return 放回链外层文本位置。
2. bare-return 消除逻辑：搜索将 `RETURN None` 判定为"与后续隐式返回重复而删除"的规则
   （可能位于 handler/statement 生成或 region 合并阶段）。注意 W13 曾在 finally 场景做过
   return 装载序列重建（_generate_handler_body_statements / _find_finally_normal_copy_blocks），
   W14-B 可参考其"装载序列→单一 Return(expr)"思路，但作用域是普通 if/else 分支。
3. elif 链重建：查找把 else 臂内嵌 if 折叠为布尔运算（`and ... or ...`）的组合条件生成器；
   该折叠仅在嵌套 if 是 else 臂唯一语句且无条件副作用时才合法，且必须保留操作数极性
   （本轮丢失了 `not`）。r05 显示连单层 `a and not b` 都会被改写成 `not (a and b)`
   （POP_JUMP 极性反转，co_code 同长但 jump 目标不同）。
4. 共享尾部 return 放置：多前驱汇合的 return 应输出在所有臂的最小公共支配块的文本末尾，
   而非任一臂内部。
