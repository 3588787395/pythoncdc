## 3. 最终判定规则

main.pyc 3/3 全 PASS 当且仅当同时消除两类根因：

- **W11-B（孤立 NOP 构造丢失）**：语句边界上的编译器折叠残留 NOP 必须以 `while False:` + 缩进 `pass` 显式还原——但四类结构性 NOP（try 帧标记 V-T / 异常表汇合锚点 V-S / 空结构体占位 V-B / 循环头锚点 V-L）由源码结构重编译时自动再生，显式构造反而引入多余字节与多余 const（False 入池导致 co_consts 整体错位）。判定全部基于异常表边界与控制流边方向，无 depth/pyc 特判。
- **W11-A/W12（finally 双副本重组 + 显式 else 分离）**：复合 finally 体以正常路径副本为唯一语句源按原偏移序重组（异常副本 RERAISE 终止语义由 try/finally 语句整体表达，不以 RETURN_VALUE 替代）；显式 else 体被编译器移出异常表保护范围后，须凭「unprotected + JUMP_FORWARD 连接子 + handler 同目标汇合」判据从 try_blocks 分离为 orelse——否则 co_exceptiontable 的 try 保护区间终点漂移（208,296 vs 208,288）。
