## 2. 偏移级差异分析（dis 级）

工具与转储：`d:\Temp\opencode\r11_disdiff.py` → `r11_run_orig.txt` / `r11_run_decomp.txt` / `r11_run_diff.txt`。

### 2.1 缺陷一（首要）：finally 体语句重排/拆分（新家族 W11-A）

原 pyc finally 体语句顺序（正常路径副本 offset 4038–4838）：

1. `if config.strategy.run_type == RunType.BACKTEST and config.plugins.plugin_system_log.enabled is False:` → `with open(...) as fa: fa.write('THIS IS THE END OF THE LOG.\n')`（with 嵌套在双条件 if 体内，offset 4128–4380）
2. `engine.event_bus.publish_event(Event(EventEnum.SYSTEM_EXIT, code=code, exception=ex))`
3. `engine.calendar_dt = None`
4. `if engine.config.strategy.run_type == RunType.TRADING:` → `if plugins_manager.load_plugin_flag is False:` → import/print/`set_trade_stop_status(...)`
5. `plugins_manager.release(code, ex)`
6. `print(_('插件卸载完成，引擎退出'))`

反编译产物（r11_main.py L150–170）实际发射为：

1. `if config.strategy.run_type == RunType.BACKTEST: pass`（条件体被抽空）
2. `plugins_manager.release(code, ex)`、`print(_('插件卸载完成，引擎退出'))`（第 5/6 句提前到首位）
3. `if plugins_manager.load_plugin_flag is False:` 分支（第 4 句）
4. 裸 `with open(...): fa.write(...)`（第 1 句被推迟且脱离其 if 守卫）
5. finally 缩进之外：`publish_event(...)`、`calendar_dt = None`、`if TRADING...`（第 2/3 句泄漏到 finally 区域外）
6. 函数尾部再复制一份 `if BACKTEST and enabled is False: with open(...): pass`（**空体 with 副本**），并以 `LOAD_CONST None; RETURN_VALUE` 结尾——异常路径副本的终止序列 `RERAISE/COPY/POP_EXCEPT/RERAISE`（原 5640–5646）被替换，导致 co_exceptiontable 188 vs 171。

指纹：**with 头部（open…BEFORE_WITH…STORE_FAST fa）与其体（fa.write…POP_TOP）被拆散到不同位置发射；兄弟线性段整体次序颠倒；出现空体 with 副本；异常副本终止符漂移**。与已修家族不同：R07 是 docstring/嵌套 if 折叠、R08 是 handler 误吸收、R09 是循环吞并兄弟块、R10 是 WithRegion 吞并紧前兄弟表达式语句（少发射）；W11-A 是**多发射+错序+重复副本**，属新家族。

### 2.2 缺陷二：语句边界孤立 NOP 构造丢失（新家族 W11-B）

co_code 首个差异 `[530] offset=3636`：原 pyc 在 `executor = Executor(engine)`（STORE_FAST@3634）与 `executor.run(bar_dict)`（LOAD_FAST@3638）之间存在一个**孤立 NOP**：

- 无任何跳转指向 3636（全量扫描 `to 3636` 为空）；
- 异常表区间 `3498 to 3732 -> 3764` 连续覆盖该位置，排除嵌套 try/finally；
- 该 NOP 使后续全部指令偏移 +2，是反编译输出 5886 vs 5648 字节膨胀之外的系统性错位起点。

实验矩阵（`d:\Temp\opencode\r11_probe7.py`）：可产生"无跳转来源孤立 NOP"的源码构造包括 `while False: pass`、空 `try/finally: pass` 包裹等编译器折叠残留；结合异常表证据，最贴合的原始构造为两语句间的死循环折叠（如 `while False: pass`）。反编译器 CFG 构建时丢弃 NOP 块且不重建任何等价构造，导致 re-compile 后从 3636 起字节级永不一致。

### 2.3 非缺陷澄清（避免修复工程师误入歧途）

以下反编译输出形态初看可疑，经字节级验证**均为正确还原**：

- **显式 `else:` 子句**（L147–149 `else: code = ExitCode.EXIT_SUCCESS; ex = None`）：原 pyc 异常表 `3734 to 3762 -> 4840`（finally 异常路径）证明尾部赋值不被 except handlers 覆盖，即源码确有 else；
- **`persist_helper.restore()` 位于第二个 `if persist_provider is not None:` 体内**（L126–132）：原 pyc 偏移 2668–3504 的控制流证实。注意 `mainOK.py` 并非本 pyc 的真实源码（其 run 编译为 5018 字节 vs pyc 5648，restore 位置亦不同），不得作为基准；
- 三引号字符串渲染 `"""THIS IS THE END OF THE LOG.\n"""`：re-compile 后常量一致。

## 3. 根因方向汇总

| 编号 | 家族 | 触发形态 | 根因方向 |
|---|---|---|---|
| W11-A | finally 体调度错乱 | finally 体内含 if(+with) 复合块 + 兄弟语句（≥10 形态复现，见 repro_01~05/09~11） | finally 区域的块排序/发射阶段：复合块（IfRegion 嵌 WithRegion）未按原偏移序插回线性段，而是延迟追加；with 头/体拆散产生空体副本；异常路径副本终止符 RERAISE 序列被 RETURN_VALUE 替换 |
| W11-B | 孤立 NOP 构造丢失 | 两语句间存在编译器折叠产生的孤立 NOP（无跳转来源、非 try 标记）（repro_06~08） | CFG 构建/代码生成阶段无条件丢弃 NOP 块，未对"语句边界孤立 NOP"重建等价源码构造 |
