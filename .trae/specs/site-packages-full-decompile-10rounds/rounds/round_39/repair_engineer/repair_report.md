## 1. 缺陷描述

`get_history`（IQEngine/api/api_base.pyc）中 `if sys_frequency in ('1m', 'tick') and include:` 的语句级菱形在反编译时被三元区域误吞并：

- 菱形 true 块含两条赋值语句（`query_date = data_proxy().get_previous_trading_date(...)`、`include = False`）加 else 体语句，修复后输出全部丢失，仅剩错误的自赋值兜底；
- 表现为编译出 81 条指令（原始 111 条），条件块 A/B/C 与 D2/D3 分支整体未发射；
- 该缺陷为 R38 遗留（R38 报告「残留移交」项）。

## 2. 根因

区域识别层 `_create_ternary_region_from_pattern` 的**放松接纳路径**（`has_jump_forward_skip` / 嵌套三元接纳）绕过了 `_is_ternary_block` 的单表达式校验，把语句级菱形误识别为嵌套三元链（偏移 152/194/198）。

缺陷触发的充要条件（probe_w40.py 形态探测结论）：

1. `query_date`/`include` 为**闭包 cell 变量**（`MAKE_CELL` + `STORE_DEREF`，被函数内 dictcomp 捕获）——STORE_FAST 简化形态不会触发（形态 A–D 修复前全 PASS）；
2. 值块含非 walrus 的 `STORE_*` 语句指令；
3. 条件为 BoolOp 短路链布局（`A and not B or C`）。

三者叠加时，值块中的赋值与 else 体语句被当作三元表达式值丢弃，违反区域归约算法「**表达式级区域不得吞并语句级块**」原则。

## 3. 修复实现

`_create_ternary_region_from_pattern` 入口处新增「值块纯度守卫」（region_analyzer.py:19400-19428），对 true/false 值块逐一检查：

1. **非 walrus STORE 拒绝**：遍历值块有效指令（剔除 `NOISE_OPS`），经 `OpcodeFeatureDetector.is_any_store()` 检测到 STORE_* 即为语句级赋值特征，判定该块不是纯表达式值块；
2. **COPY 1 walrus 豁免**：STORE 前紧邻 `COPY 1`（经 `is_copy()` 判定 + `arg == 1` 校验）时豁免——walrus 值块（`(x := expr)` 编译为 `expr; COPY 1; STORE x`，原值留栈供表达式使用）是合法表达式值块形态；
3. **尾部 JUMP 剥离**：剥离值块尾部无条件跳转（`is_unconditional_jump()`：JUMP_FORWARD / JUMP_ABSOLUTE / JUMP_BACKWARD / JUMP_BACKWARD_NO_INTERRUPT），避免块尾控制流指令干扰 STORE 检测；
4. **触发即 `return None`**：交由 IfRegion 按语句级结构归约——区域归约算法「一次正确」，表达式级区域不得吞并语句级块。

实现全程使用 `OpcodeFeatureDetector` 谓词（`is_any_store` / `is_copy` / `is_unconditional_jump`），无硬编码 opname。

### 本轮合规复核修正（2 处）

修复工程师复核时发现守卫初版存在 2 处硬编码 opname，已替换为 detector 谓词并复验（见第 5 节）：

- 尾部 JUMP 剥离 `opname in ('JUMP_FORWARD', ...)` → `is_unconditional_jump()`（含 CONTINUE_LOOP / JUMP_NOT_EXC_MATCH，语义兼容）；
- walrus 豁免 `prev.opname == 'COPY'` → `is_copy()`。
