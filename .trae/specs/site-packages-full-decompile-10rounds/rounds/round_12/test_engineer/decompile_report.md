## 根因判断

**新家族 W12（except 匹配表达式截断），非已修家族残留变体。**

与已修家族的区分：
- R07 docstring/嵌套 if 折叠——无关（本轮无 docstring/if 差异）；
- R08 boolop 链尾豁免/handler **误吸收**——R08 处理的是 handler 边界归属错误，本轮是 handler 的 exc_type 表达式内容残缺；
- R09 循环吞并兄弟块、R10 with 吞并兄弟表达式语句、R11 finally 重排/孤立 NOP——本轮无循环/with/finally 结构差异。

### 根因链（嫌疑方法线索，供修复工程师）

1. **主嫌**：`core/cfg/region_analyzer.py:8026-8043` `_extract_except_handler`——收集 PUSH_EXC_INFO 之后、CHECK_EXC_MATCH 之前的表达式时只认 `LOAD_NAME/LOAD_GLOBAL` 的 argval 字符串：
   ```python
   if instr.opname in ('LOAD_NAME', 'LOAD_GLOBAL'):
       pre_check_instrs.append(instr.argval)
   ```
   `LOAD_ATTR`（注意 3.11 arg 低 1 位为 method 标志）、`BINARY_SUBSCR`、`CALL` 等被静默丢弃 → exc_type 只剩根名；非 Name 根（下标/调用）时 pre_check_instrs 为空 → exc_type=None。
2. **放大点**：`core/cfg/region_ast_generator.py:19101-19111`——字符串 exc_type 直接包装为 `{'type': 'Name', 'id': str(exc_type)}`；exc_type=None 时 handler_node 不设 exc_type。
3. **退化终点**：`core/cfg/ast_converter.py:1405-1406`——exc_type 为 None 时 type_node=None，最终发射裸 `except:`。

修复方向建议：
- 在 `_extract_except_handler` 中对 pre-CHECK 区间做完整表达式栈重建（LOAD_ATTR 点链拼接、BUILD_TUPLE 元组、BINARY_SUBSCR 下标），或直接产出完整表达式 dict（handler_node['exc_type'] 已支持非 str dict 直通）；
- 无法识别时保守回退为 `Exception` 或报错标记，**严禁退化为裸 except:**（语义反转级缺陷）；
- 注意 `_follow_except_chain` 及 debug 系列副本存在同构逻辑，修主路径即可，但需确认实际调用走的是 region_analyzer 主类。

## 结论

- wrapper.pyc 4 个 code object 中 1 个真实缺陷（api_exec_patcher.wrapper），模块级 2 个 FAIL 为嵌套 code 连带；
- 缺陷属新家族 W12：**except 异常匹配表达式的非根成分被丢弃**；
- 触发条件单一且确定：CHECK_EXC_MATCH 前存在 LOAD_ATTR/BINARY_SUBSCR/CALL 等非 LOAD_NAME/LOAD_GLOBAL 指令。
