### core/cfg/region_ast_generator.py

> 注：工作树中已存在前一会话遗留的未提交 W15-A/B/C/D/E、R15-10 初版实现。本会话验证其可复现 13/13 后，发现并修复了三类缺陷：① vc 路径仍吞同块前驱语句与 merge 后继控制流（W15-E'）；② W15-C 判据过宽导致批量 9 文件回归（详见三）；③ `stack_effect(op, arg=...)` 关键字调用 TypeError 被裸 except 吞掉。

1. **`_generate_value_context_chain_compare_assign`**（W15-E' 主修）
   - 新增前驱语句提取：`_pre_stmts = self._extract_vc_pre_store_statements(cond_block)`，Assign 与后继语句一并返回 `[pre..., Assign, post...]`。
   - 新增 `_trailing_control_open` 分支：merge_block 中 STORE 后缀剥离隐式 return None 后若含条件跳转类指令且存在以 merge_block 为 entry 的兄弟区域，则 `generated_blocks.discard(merge_block)`，交由该区域按 CFG 正常生成嵌套 if 等后继语句（内联重建无法跨块）。
2. **`_extract_vc_pre_store_statements`**（新增方法，W15-E' 判定）
   - 结构判据：正向栈深模拟——定位块内首个 SWAP（链式比较特征），自块首累计 `dis.stack_effect(opcode, arg)`，SWAP 前最后一个「栈深归零点」即完整前驱语句与比较表达式的分界；前缀须直线代码（无 JUMP*/POP_JUMP*/RETURN*），深度 <0（操作数来自前驱块）时放弃。
   - price_validator 形态：`next_trading_date = self._engine.data_proxy.get_next_trading_date(...)` 与链式比较同块（orig offset 282–344），原实现只重建 Compare 致整句蒸发、`next_trading_date` 沦为悬空 LOAD_GLOBAL。
3. **`_merge_block_is_then_exclusive`**（W15-C 判据收紧，消除批量回归）
   - 新增第 2 条结构判据：then 臂自身必须无有效语句（剔除 RESUME/NOP/CACHE/PUSH_NULL/POP_TOP/JUMP*/POP_JUMP* 连接件后无剩余指令）。真身整体位于 merge_block 是 CPython「条件跳转跨过真身」布局的特征；普通 if/else 的 then 体含实际语句时 merge_block 只是顺序续接点，不得归入 then 体。
   - 原「假出口前向可达性」单判据在 else 臂以 return 终结时误判（conver_int14_to_string：else return 使 merge 不可达 → 误吸入 then 体，吞并后继第二条 if）。
4. **then 体扫描处 merge_block 强制标记加兄弟区域守卫**（~L11473）
   - merge_block 同时是另一区域 entry 时不再强制标记 generated（避免该区域被跳过、后继控制流蒸发），其余场景维持原行为。

## 四、最终判定规则（供后续轮次复用）

- **链式比较中缀操作数**：以「首个 SWAP」为锚，逆向保证 [left, middle] 栈布局，各段经 expr_reconstructor 完整重建；禁止单条 LOAD 提取或字面量占位（W15-A）。
- **vc 链式比较赋值的同块兄弟语句**：
  - STORE 前：正向栈深模拟取最后一个归零点为分界，前缀直线代码重建为前驱语句（W15-E'）；
  - STORE 后：剥隐式 None-return 后，直线 RETURN 后缀内联重建（W15-B）；条件跳转后缀且存在以 merge 为 entry 的兄弟区域时不标记 generated，交由区域生成器（W15-E'）。
- **真臂专属汇合块归入 then 体**须同时满足：merge 不在两臂列表 ∧ **then 臂自身无有效语句** ∧ 假出口前向不可达 merge（W15-C 收紧版）。
- **显式 return None 发射门控**：≥2 条件跳转边汇聚的裸 return None 块背书 `_explicit_return`，不得按隐式返回剥离（R15-10）。
