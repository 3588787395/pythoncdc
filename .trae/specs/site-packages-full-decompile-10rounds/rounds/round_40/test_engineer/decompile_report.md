## 2. 根因分析

### 2.1 add_end_flag —— if/elif/else 的 merge 后继区域（for 循环）被误挂为 IfRegion 子区域

**原始语义**（反汇编 `dis_add_end_flag.txt`）：

```
  48 if isinstance(backtest_id_list, str):   # POP_JUMP_FORWARD_IF_FALSE -> 56
  48     backtest_id_list = [backtest_id_list]
  54     JUMP_FORWARD -> 210                  # then 分支跳到共享后继
  56 elif isinstance(backtest_id_list, list):
  98     JUMP_FORWARD -> 210                  # elif 分支（空体）跳到共享后继
 100 else:
 100     log.error(...); return False         # 100-208
 210 for backtest_id in backtest_id_list:    # for 循环 = if/elif/else 的平级后继
```

即 for 循环 header（块 210/216）位于 if/elif/else **之外**，两个真路径分支都跳向它。

**区域分类证据**（`probe_regions.py`）：

- 识别侧 merge 判定正确：IfRegion `merge=210`、then=[48]、else_blocks=[56, 98, 100, 206]。
- **但区域树根节点为**：`IfRegion(min_block=6, children=[LoopRegion(first_block=210)])`——merge 块上的 for 循环被挂为 IfRegion 的**子区域**，而非父序列上与 IfRegion 平级的后继。

**生成侧证据**（`probe_ast.py` → `ast_module_add_end_flag.json`）：`For` 节点位于 `If.orelse[0].body`（elif 分支体内），else 分支（log.error/return False）被移到循环之后；输出源码中出现 `for ... else: return True` 嵌套在 elif 内 + 4 处 `if True: pass` 残迹。

**后果**：指令集相同（299=299）但顺序全错（248 diffs）——decomp 把 for 循环体放在 else 分支之前（elif 体内），orig 相反。

**违反的算法原则**：分支收集越界 / merge 块归属——分支收集须止于最近公共支配后继（merge 块 210）；merge 块及其上的后继结构属于父序列，应与 IfRegion 平级（原则 3「嵌套即抽象节点」、原则 4「父区域引用子区域入口」的边界语义）。

**归因**：region_analyzer 层次构建（LoopRegion 父指针挂错到 IfRegion）→ region_ast_generator 的 elif 链发射顺延把循环收进 elif 分支体。次要问题：循环体内 `if not end_sentence_count != 2: continue`（偏移 1232-1260）双重否定极性（W39 相关域）。

### 2.2 creat_sheet2 —— 三元（内嵌调用实参）的 merge 块吞并块内后续语句

**原始语义**（`dis_creat_sheet2.txt`）：stock 分支 j 循环（1318-2340）内：

```
1856 sheet.write(row, 3, '买' if transactions['amount'] > 0 else '卖')   # 三元内嵌 write 实参
     # 三元：cond 块 1706（含 write 0/1/2 前导语句 + LOAD write 实参准备）、
     #       值块 1908('买')/1912('卖')、merge 块 1914
1914 merge 块：CALL write + POP_TOP（write3 收尾）
1932-2330        sheet.write(row, 4, abs(...)) / write(row,5, float(...)) / write(row,6, float(...*...)) / write(row,7, float(...))
2336 row += 1；2340 JUMP_BACKWARD -> 1318
```

future 分支同构（trade_type if/elif 链 3170-3312 + 开/平三元 3360-3416，merge 块 3416 承载 write 5-8 + row += 1 + 回边）。

**区域分类证据**（`probe_regions.py`）：三元识别正确——

- stock：`TernaryRegion content=[1706, 1908, 1912, 1914]`，位于 j 循环 LoopRegion 内；
- future：`TernaryRegion content=[3312, 3410, 3414, 3416]`。

**生成侧证据**（`ast_module_creat_sheet2.json`）：

- stock 分支 j 循环体仅 11 条语句（应为 15 条：6 赋值 + 08:00 If + **8 条 write** + row AugAssign），`sheet.write(row, 3..6, ...)` 4 条丢失；
- future 分支 j 循环体 `write 4-8` 5 条丢失；
- **全 AST `IfExp` 计数 = 0**——三元本体也未被发射。

**违反的算法原则**：语句级块被表达式区域吞并——TernaryRegion 的 merge 块同时承载「三元结果消费语句（CALL write 收尾）」与「多条后续语句级指令」；`_generate_ternary` 消费 merge 块后只重建到三元消费之前的部分，剩余语句未按「每块唯一归属」回注父序列发射，导致三元及其消费语句、后续 4-5 条 write、row += 1 部分丢失（orig 651 → decomp 505，缺失 146 条指令）。

**归因**：region_ast_generator（`_generate_ternary` 的 merge 块处理），非 region_analyzer（识别正确）。

### 2.3 backtest_download_result —— while 循环出口分支收集（R4-08 BFS）越界吞并函数尾部

**原始语义**（`dis_backtest_download_result.txt`）：

```
547 if os.path.exists(file_path):
548     df = pd.read_csv(...)
549     if len(df) > 1: df = df[:-1]
551     while len(df) > 1 and list(df[-1:].index)[0] == END_TIMESTAMP:   # 底部闩锁重测 588-710
552         df = df[:-1]
553-557 for i in range(len(df)): df['orders'/'positions'/'transactions'][i] = _str_to_list(...)
558-573 if len(df)==0 ... data 三元 ... json.loads ... creat_sheet1/2/3 ...
574-576 file_name = os.path.join(...); book.save(file_name); return True      # 偏移 1588-1710
```

**区域分类证据**（`probe_regions.py`）——while 的 LoopRegion：

```
LoopRegion body_blocks=[568, 626]
           else_blocks=[712, 750, 836, 892, 894, 1114, 1152, 1194, 1280, 1286,
                        1332, 1344, 1356, 1398, 1588, 1708]
```

`else_blocks` 从循环出口 712 一直吸收到**函数末尾 1708**（16 个块）。成因链：

1. 整个函数位于 try 内 → 循环条件块的异常后继（1712 PUSH_EXC_INFO）混入 loop_successors；
2. `find_nearest_common_post_dominator` 对 {712, 1712} 求解失败（None）→ 进入 `_find_loop_else` 的「R4-08 BFS 扩展」分支（region_analyzer.py:4724 起，WHILE_LOOP 专用）；
3. BFS 从出口后继 712 出发收集一切可达块，且不受 R09 `_is_post_merge_sibling_head` 归还机制约束。

**后果**：

- 外层 IfRegion(offset 342, merge=1588) 的 merge 块 1588/1708 被循环认领 → `book.save` / `return True` 丢失；
- while 无 break 证据 → else_blocks 不映射为 orelse → 循环后 141 条指令（553-576 行全部语句）整体缺失（orig 301 → decomp 160）；
- 底部闩锁重测块（588-624，`len(df) > 1` 复测）未被吸收进 while 测试，生成伪 `if len(df) > 1: break`（极性亦反）。

**违反的算法原则**：分支收集越界 / merge 块误判——loop-else 仅在有 break 证据（后必经路径证明）时成立；无证据的顺序后继属父序列（原则 2「每块唯一归属」：这些块同时是外层 IfRegion 的 then 分支内容）。

**归因**：region_analyzer（`_find_loop_else` WHILE_LOOP BFS 扩展，region_analyzer.py:4724-4808）。

## 6. 修复建议（供 Round 41 参考，本轮未改核心代码）

1. **add_end_flag 型**：区域层次构建时，merge 块上的后继区域不得挂为 IfRegion 子区域——应以 IfRegion 平级身份挂父序列（生成侧 elif 链发射同步加分支封闭守卫）。
2. **creat_sheet2 型**：`_generate_ternary` 消费 merge 块时，须把「三元消费语句之后」的剩余指令按栈纪律切分回父序列发射（复用 `_split_block_condition_prefix` 的栈深判据思想，方向相反）。
3. **backtest_download_result 型**：`_find_loop_else` 的 WHILE BFS 扩展分支应排除异常后继对 natural_exit 求解的污染（R32 修复仅覆盖 FOR 分支），并对 BFS 结果施加 `_is_post_merge_sibling_head` / break 证据约束。
