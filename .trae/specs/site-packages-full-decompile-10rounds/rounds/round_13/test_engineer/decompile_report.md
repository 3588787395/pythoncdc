## 五、根因方向

### 判定：新家族 W13 —— 「finally 尾部单条 return 语句的返回值丢失」（R11 W11-A finally 重排的未覆盖变体）

不是 R07-R12 已修家族的直接残留：docstring/嵌套 if（W07）、boolop/handler 吸收（W08）、循环吞并（W09）、with 吞并（W10）、finally 重排/孤立 NOP（W11）、except 匹配截断（W12）的修复在本例中均已生效，缺陷出现在其后的 finally 体语句组装阶段。

### 缺陷机制（已插桩实证，见 d:\Temp\opencode\r13_trace.py / r13_blocks.py）

CPython 3.11 对 `try: body \n finally: return v` 生成 finally 双副本：

| 块 | 内容 | 角色 |
|---|---|---|
| block@18 | `LOAD_FAST v; RETURN_VALUE` | finally 正常路径副本 |
| block@22 | `PUSH_EXC_INFO; LOAD_FAST v; SWAP 2; POP_TOP; SWAP 2` | 异常副本前段（弃异常保值） |
| block@32 | `POP_EXCEPT; RETURN_VALUE` | 异常副本尾段 |
| block@36 | `COPY 3; POP_EXCEPT; RERAISE 1` | RERAISE 清理帧 |

RegionAnalyzer 给出 `TryExceptRegion(entry=8, blocks=[8,18,22,32,36], finally_blocks=[22,36,32], has_finally=True)`，正常路径副本 block@18 游离为独立 Region(entry=18)。

发射阶段（region_ast_generator.py `_generate_try` finalbody 组装，走 legacy 分支，`_w11a_nc_blocks` 为空）：

1. **block@18 从未被派发生成** → `Return(v)` 整体丢失；
2. **block@22** 经 `_generate_handler_body_statements` 过滤 PUSH_EXC_INFO/POP_TOP 后，`LOAD_FAST v` 被当裸表达式 → 发射 `Expr(v)`；
3. **block@32** 过滤 POP_EXCEPT 后只剩 RETURN_VALUE，无值表达式可重建 → 回退伪造 `Return(Constant None)`；
4. block@36 全为框架指令 → 空。最终 `finalbody=[Expr(v), Return(None)]`，与 AST 插桩输出完全吻合。

### 形态边界（12 例探测，d:\Temp\opencode\r13_probe.py / r13_validate.py）

| 形态 | 表现 |
|---|---|
| A 组：finally 尾部 `return <expr>`（局部变量/调用/属性/下标/赋值后 return） | `Expr(<expr>)` + `Return(None)`，双路径返回值丢失 |
| A 循环变体：for/while 体内 try-finally-return | 同 A，另伴循环体偏移漂移 |
| A 嵌套变体：嵌套函数/嵌套 try 外层 finally return | 同 A，作用于内层/外层对应函数 |
| B 组：finally 尾部 `return <const>` | 正常副本被吞 + 异常副本误发射为裸 `except:` 子句（结构改写，比 A 更严重） |
| 对照组：finally 含 if/else 双 return、finally 无 return 仅后续 return | 均正常 PASS（嵌套控制流使 return 不在 finally 直接子级尾部） |

### 旁注

`ast_generator_v2.py:18337 _remove_returns` 存在同类「finally 内 return 降级为 Expr」逻辑（注释断言"finally 块不应该有 return"，与 Python 语义不符）。该模块不在默认管线（use_region=True 走 RegionASTGenerator）中，但若切换管线会复发，修复时应一并审视。
