## 4. 残留 2 项差异的可豁免性裁定（L1 口径，已确认无法通过反编译器修复）

### 残留1：`<module>` -59 NOP（PEP626 多行签名续行行追踪）

- **根因**：CPython 3.11 PEP626 对「装饰器 + 多行函数签名（默认参数各占一行）」在 module 级别插入 NOP 追踪行号。实测：装饰器+多行签名 module级 NOP=3，装饰器+单行签名 NOP=0。
- **为何无法修复**：反编译器单行输出函数签名（`def f(a=1, b=2, c=3):`）是语义等价的排版选择，无法恢复原始源码的多行排版（`def f(a=1,\n b=2,\n c=3):`），故无法生成对应的行追踪 NOP。
- **裁定**：✅ 可豁免。NOP 是 CPython 排版追踪，与控制流语义无关，反编译器输出单行签名正确还原了函数语义。

### 残留2：build_future_fill_time frozenset（CPython 常量折叠）

- **根因**：反编译产物第424行 `market_time = {'14:30:00', '14:00:00', ...}`（set literal），CPython 重编译时对 set literal 做常量折叠优化为 frozenset（实测：`x in {'a','b','c'}` 编译为 `LOAD_CONST frozenset`）。orig pyc 的 frozenset 是 CPython 对原始 set literal 的折叠结果。
- **为何无法修复**：反编译器正确还原了 set literal `{...}`（原始源码就是 set literal）。若输出 `frozenset({...})` 可精确匹配字节码，但那不是自然的源码还原。重编译时 CPython 再次折叠，但 frozenset 的内存地址/元素顺序不可控。
- **裁定**：✅ 可豁免。set literal 是正确的源码还原，frozenset 差异源于 CPython 常量折叠优化，非反编译缺陷。

## 5. 4 项归一化豁免的合理性裁定（终版）

| 豁免项 | 合理性 | 理由 |
|--------|--------|------|
| 跳过 CACHE | ✅ 永远合理 | CPython inline cache slot，纯执行时缓存，重编译必然重新生成 |
| 跳过 NOP（仅限 PEP626 行追踪）| ✅ 合理 | 多行签名续行 NOP，反编译器无法恢复原始排版；**但 NOP 增减也可能是真实控制流缺陷信号，需逐项核查**（R25/R26 已证）|
| EXTENDED_ARG | ⚠️ 需警惕 | EXTENDED_ARG 增减可能是真实结构差异信号（R26 缺陷3 就是 EXTENDED_ARG +1 暴露的）；修复后应趋于 0 |
| code 递归忽略元数据 | ✅ 永远合理 | co_filename/co_firstlineno/地址不可恢复 |
| 跳转目标等价 | ✅ 合理 | 覆盖 CPython 重编译对齐偏移（修复真实缺陷后仅剩合理偏移）|
| 常量 set/frozenset 等价 | ✅ 合理 | CPython 常量折叠，set literal 是正确还原 |

## 6. 结论（终版）

1. **用户判断正确**：NOP/EXTENDED_ARG 增减确实暴露真实控制流缺陷。R25 修复了 build_future_fill_time 的 NameError 级缺陷，R26 修复了 one_prod_to_dataframe 的 AST 形状不一致，两轮共消除 2 个真实缺陷。

2. **比较方法应采用分级口径**：
   - **主口径（归一化）**：150/150 = 100%，用于交付确认
   - **辅助诊断口径（L1）**：148/150 = 98.67%，用于发现真实缺陷；残留 2 项已确认可豁免
   - **L1 口径下 NOP/EXTENDED_ARG 差异必须逐项核查**，不可一概豁免为"对齐偏移"

3. **不应进一步收紧到纯逐条 dis**：那会把 code object 元数据（filename/firstlineno/地址）误报为不一致。

4. **最终状态**：
   - 归一化：150/150 = 100.00%
   - L1（严格）：148/150 = 98.67%，2 项残留均经实测确认可豁免（PEP626 NOP + CPython 常量折叠）
   - 操作码层面：0 真实控制流缺陷
   - 测试矩阵：318 pass / 9 fail / 11 skip，0 退化
   - 反模式自检：0 新增
