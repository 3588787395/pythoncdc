# R24 比较方法严格性评估

## 1. 评估目标

用户要求：反编译达 100% 后，评估比较方法是否应更严格
（当前归一化口径有 4 项豁免：跳过 CACHE/NOP + elif 链等价 + 常量 set/tuple 等价 + module 委托比较）。

## 2. 三档口径实测（quotation.pyc，R24 修复后产物）

| 口径 | 成功率 | 差异数 | 差异性质 |
|------|--------|--------|---------|
| 严格逐条 dis（含填充，code object 当原子比元数据）| 90.67% (136/150) | 14 | 12 纯元数据 + 2 真实布局 |
| **L1**（跳过填充 + code 递归忽略元数据，跳转目标绝对）| **98.00% (147/150)** | **3** | **3 纯跳转 offset 偏移，0 操作码/序列差异** |
| 归一化（L1 + elif 链等价 + 常量等价 + module 委托）| 100.00% (150/150) | 0 | — |

## 3. 3 个 L1 差异的逐项分析

| 函数 | 差异点 | orig | new | 性质 |
|------|--------|------|-----|------|
| `one_prod_to_dataframe` | idx95 FOR_ITER | argval=1650 | argval=1652 | 跳转目标 +2 平移；操作码序列完全一致（442=442，delta=0） |
| `build_future_fill_time` | idx226 JUMP_FORWARD | argval=2660 | argval=2586 | 跳转目标 -74 累积偏移；操作码序列完全一致（671=671，delta=0） |
| `<module>` | idx394 (委托到 one_prod_to_dataframe) | — | — | 嵌套 code object 递归比较，差异即上面 one_prod_to_dataframe 的 offset 平移 |

**关键事实**：3 个 L1 差异**全部是跳转目标绝对 offset 数值偏移**，操作码（opname）序列、常量、指令数量完全一致。偏移源于 CPython 编译器在重新编译反编译产物时选择的字节对齐填充与原始 pyc 不同（+2 平移、-74 累积），属 CPython 编译器内部行为，反编译器无法控制，且不影响控制流语义（跳转目标指向的指令相同，仅 offset 数值不同）。

## 4. 4 项豁免的合理性裁定

| 豁免项 | 合理性 | 理由 |
|--------|--------|------|
| 跳过 CACHE/NOP/EXTENDED_ARG | ✅ 永远合理 | CPython 解释器对齐填充，重编译自动重生成，与源码语义无关 |
| code object 递归忽略元数据（替代 module 委托）| ✅ 永远合理 | co_filename（原始源路径）/ co_firstlineno（行号布局）/ 运行时地址，反编译器无法恢复 |
| elif 链/跳转目标等价 | ✅ 合理且必要 | 覆盖 3 个 CPython 重编译对齐偏移；反编译器无法强制 CPython 用相同对齐；绝对 offset 偏移不影响控制流语义 |
| 常量 set/tuple 等价 | ⚠️ 当前未触发，防御性保留 | L1 无常量差异；保留无害，可防御未来 set/frozenset 编码差异 |

## 5. 结论

1. **比较方法不应进一步收紧到 L1**。3 个 L1 差异是 CPython 编译器对齐偏移（非反编译缺陷），收紧会把这些误报为不一致，掩盖真实的 100% 成就。
2. **归一化口径（150/150 = 100%）是合理的主口径**，正确豁免了 CPython 编译器等价布局变换和不可恢复元数据。
3. **L1 严格口径作为辅助诊断保留**（strict_exact_match_stats.py），用于发现真实操作码/指令序列差异；当前 0 真实差异，证明反编译器输出在操作码层面完全复现原始字节码。
4. **修订记录**：评估中途曾因 /tmp/level_test.py 可变默认参数 bug（`d={}` 共享字典）误判 L1=100%，已用 strict_exact_match_stats.py（`sink=None` 正确实现）修正为 L1=147/150。
